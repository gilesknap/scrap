# HTTP API and CLI

Reference for scrap's HTTP API, command line and settings. Requests and responses are JSON unless noted.
Responses of text (JSON, the PWA's scripts, styles and pages) over 1 kB are gzipped for a client
that sends `Accept-Encoding: gzip`; stored files, previews, downloads, fonts and range requests
never are.
The service listens on `127.0.0.1`, or with `scrap serve --uds` only on a Unix socket (the
single-server install's default), and has no login; put Tailscale Serve (or an authenticating
proxy) in front. The author of a capture or edit is the `Tailscale-User-Login` header (or the header named by
`SCRAP_IDENTITY_HEADER`), else `tagged`; a header naming `claude` (MCP's author) counts as none.
A text revision made over HTTP is always source `web`, never Claude's.

## HTTP

### Host and Origin

Every route but `/mcp` (which has its own, the same check) and `/healthz` checks the request's
`Host` and `Origin`, against the allow-list `/mcp` uses ([](mcp.md) has its rules), so one setting,
`SCRAP_PUBLIC_URL`, covers both. This stops another web page from reaching scrap through your browser:
a DNS rebinding page (its name as `Host`) and a form or `fetch` it sends from its own site.

- **Host**: loopback (`127.0.0.1`, `localhost`, `[::1]`, any port) or a host of `SCRAP_PUBLIC_URL`,
  else `421`. Case and a trailing dot are ignored; two `Host` headers are refused. On these routes
  an IP address is always accepted, so the web app of an install reached at
  `http://192.168.1.10:8000` needs no setting; `/mcp` does not accept a bare IP address, so list it
  in `SCRAP_PUBLIC_URL` for Claude Code. A *name* (a MagicDNS or LAN hostname, a Cloudflare or Serve
  address) must be in `SCRAP_PUBLIC_URL`, as it must for `/mcp`. `X-Forwarded-Host` is ignored: the
  proxy must pass the public `Host` through (Tailscale Serve and Cloudflare do).
- **Origin**, on `POST`, `PUT`, `PATCH` and `DELETE` only: none sent (curl, the CLI, the hooks) is
  accepted; one sent must be a loopback `http://` origin or a `SCRAP_PUBLIC_URL` origin, or, for an
  install reached by IP address, that address and port. Anything else, `null` included, is `403`, as is any write the browser marks `Sec-Fetch-Site: cross-site`. The one exception is `Origin: null` on `/share` with `Sec-Fetch-Site: none` or `same-origin` (the Android share sheet, if the service worker did not take the POST).
  Browsers always send `Origin` on a cross-site write, so a page cannot leave it off.

### Errors

An error is a JSON body `{"detail": ...}` with the status that says what went wrong (the two
Host and Origin refusals are plain text instead, `Invalid Origin header` and `Invalid Host header (add its
address to SCRAP_PUBLIC_URL)`):

- `403`: a write (any method but `GET`, `HEAD` or `OPTIONS`) whose `Origin` header is not allowed.
- `421`: a `Host` header that is not allowed. Both checks are described under [Host and Origin](#host-and-origin).
- `400`: a multipart text field (`text`, `url`, `title`...) over 1 MiB, refused by the form
  parser before scrap sees it; the body is `{"detail": "Part exceeded maximum size of 1024KB."}`.
  A JSON body of that size is `422` instead (see `POST /api/captures`).
- `404`: no such page, capture, photo, drawing version or stored file. A page in the trash is not
  found either, except by the undelete route. So is a path that is neither under `/api` nor one of
  the PWA's routes below, and a PWA route with a trailing slash (`/todos/`): `{"detail": "Not
  Found"}`, with no fallback to the PWA.
- `409`: a conflict. A stale page edit (`rev` in the body is the current revision) or a stale
  drawing edit (`version` is the current version); also *Ask Claude* while enrichment is off.
- `413`: over the upload limit (`SCRAP_MAX_UPLOAD_MB`) or, for a drawing, 8 MB.
- `422`: invalid. `detail` is a string for a rule scrap checks, but a list of validation errors
  for a malformed query parameter or body (for example `limit=501` on `GET /api/pages`).
- `503`: as listed for the route (the worker has stopped, the PWA is not built, the preview decoder
  is busy). The one error that is not JSON is the PWA-not-built `503`, which is plain text: the
  build command, `npm --prefix web ci && npm --prefix web run build`, and a note that the API
  works without it. The service logs the first line of it as a warning at start. Without the PWA,
  `/api`, `/healthz` and `/mcp` work as usual.

Stored files and previews are content-addressed, so they are served with `Cache-Control: private,
max-age=31536000, immutable`, `X-Content-Type-Options: nosniff` and `Content-Security-Policy:
sandbox` (an uploaded HTML file cannot run scripts). A SHA-256 is 64 lower-case hex digits (the
`uses` and drawing routes also take upper case); any other value, or a file not stored, is `404`. A page download is `Cache-Control: no-store`. The
PWA's hashed files under `/assets/` are `immutable`; its other files are `no-cache`, so a new
build is noticed.

### The page object

`GET /api/pages/{id or slug}` (and every route that returns "the page") gives `id`, `slug`,
`title`, `body`, `kind`, `kind_fixed`, `fields`, `created_at`, `updated_at`, `rev`, `tags`,
`removed`, `tasks` (`{done, total}`), `due` and `priority` (`null` unless a todo), and:

- `made_by`: who made the page, `human`, `claude` (written over MCP), `topic` (Claude's topic page)
  or `gc` (a `scrap gc` review page), stored when the page is made and never changed, whatever
  its kind or edits later; see {ref}`page-roles`. Not `fields.origin`, the
  provenance Claude gives a page it writes over MCP.
- `captures`: each with `id`, `kind` (`note`, `url`, `photo` or `file`), `text`, `url`, `source`,
  `author`, `created_at`, `received_at` and `blobs`: one `{sha256, mime, size, filename, ingest}`
  per file, where `ingest` is as described for the route below.
- `model_tags`: the tags Claude added that are still on the page.
- `related`: pages Claude picked, pages that link here, pages a board's write-up links to or
  whose write-up links here, and pages a topic's synthesis cites or topics whose synthesis cites
  this page, each `{id, slug, title, kind, via}` (`via`: `claude`, `link`, `both`, `writeup` or
  `topic`).
- `enrich`: `{on, state, error, reason, summary, producer, source, at}`, or `null` if the page was
  never asked about and enrichment is off. `state` is `queued`, `processing`, `done`, `failed` or
  `paused` (queued while the shared queue is paused: `reason` says why, as in `GET /api/ingest`).
- `writeup`: Claude's write-up of a board page (a whiteboard or diagram image, not a list of
  actions): `{board, on, guidance, state, error, outdated, current}`, or `null` for a page with
  none and no board. `board`: whether one can be written; `on`: enrichment is on; `guidance`: the
  owner's for the next one; `state`: its latest write-up or Ask job's, as `enrich.state`;
  `outdated`: the current write-up is outdated, as `is:outdated` has it (a
  board image read, or the page's text, title, kind or tags changed, since it was made, or an
  older prompt, or its text links a page in the trash or gone; always `false` for a topic's synthesis, which the
  weekly pass remakes); `current`: `null` or `{producer, created_at, prompt_version,
  summary, text, guidance, links}` (`text` is Markdown, its links `[[slug]]`;
  `links`: the slugs of the pages, not in the trash, it links to: the PWA links no others).
  A topic page's synthesis is its write-up: the same object, with `topic` true (`board` false).
- `topics`: the topics (not in the trash) the page is a source of, each `{id, slug, title}`.
- `topic`: `null`, or for a topic page (one Claude made for a recurring thing, its `body` the
  owner's notes: see {ref}`ingest-topics`) `{key, sources}`, `sources` each `{id, slug, title,
  kind, added_by, added_at, excluded}` (not in the trash; `excluded` 1: the owner took it out).

The rows of `GET /api/pages` and of a search are the page without `body`, `captures`, `tags`,
`removed`, `rev`, `model_tags`, `related`, `enrich`, `writeup`, `topics` and `topic`, plus `thumb`; search rows also have no
`kind_fixed` or `created_at`, and have a `snippet`, and `topic` as a boolean: whether it is a topic page.

| --- | --- |
| `GET /healthz` | Liveness: `{"status": "ok", "version": ..., "max_upload_bytes": ..., "paused": ...}` (`paused`: why the Claude queue is paused, `credit`, `auth`, `budget` or `outage`, else `null`); the PWA checks a capture's size against the limit before saving it. `503` (`"status": "ingest worker stopped"`) if ingest is on and its thread has died |
| `POST /api/captures` | Save a capture as a new page. JSON `{id, text?, url?, kind?, source?, created_at?, due?, priority?, tags?}`, or `multipart/form-data` with the same fields (a `tags` field per tag) plus one or more `file` parts (`file`, singular; `POST /share` takes `files`). `id` is a ULID minted by the client (any case; stored upper case): `201` the first time, `200` with the same reply on a retry. The `id` is all a retry is matched on: the repeat is checked like any request (`422` if it is invalid), then answered with the first save's reply and its text, files and tags thrown away, so changed content needs a new `id` (files sent with a retry are stored, but no page uses them; `scrap gc` clears them). `kind` (`note`, `todo`, `consume`, `whiteboard` or `document`) is the user's choice: it fixes the page kind (`kind_fixed`, so ingest keeps it) and fills its default `fields`; without it the page is an unfixed `note`. `hint` (`todo` or `consume`) is the older name for `kind`, still accepted. `source` is `pwa` (the default) or `share`; `mcp` is refused here: only the MCP server writes it, so it marks a page Claude wrote. `due` and `priority` are a todo's only (as for `PATCH`; `422` with another kind); a `snoozed_until` sent is ignored (Snooze was retired, 28 Oct 2026). `tags` (a list of strings) are the new page's tags, cleaned as `PATCH` cleans them (`422` for a bad one, and nothing is saved), indexed at once; Claude's tags for a photo join these on its first reading of it (a later Reprocess adds them only to a page with none, so a tag the user took off stays off). A bare URL sent as `text` is treated as `url`. The capture's own kind is derived: `photo` if any of its files is an image (its images are sent to Claude, and stored before its other files, keeping the order sent, so the page's title, tags and kind come from an image; a PDF or text file among them is still read for search), `file` for other files only, else `url` if it has a `url`, else `note`. A file part sent with no content type, an empty one or `application/octet-stream` is typed from its filename's extension, else kept as `application/octet-stream`; one sent with a type that is neither an image nor a PDF, text or Markdown type (a phone's `text/x-markdown`) takes its filename's type when that is one of those; and a file's stored type is the one it was first saved with, whatever a later upload of the same bytes says. For each image file, `![](/api/blobs/<sha256>/preview?size=2048)` is added to the end of the page's `body`, after the `url` and `text` (once per distinct image, and not for one the text already links by its address), so the `body` of the page is longer than what was sent (see {ref}`images-in-the-text`). With the multipart field `place` set to `1` (the PWA composer's, #403), the `text` places its own files with tokens: `⟦image N⟧` or `⟦file N⟧` (also `⟦file N: any name⟧`), `N` the file's place among the request's `file` parts, from 1. Each is replaced by that file's embed: an image's as above, any other file's link `[filename](/api/blobs/<sha256>)` (brackets and backslashes left out of the name); the word `image` or `file` is a hint only, the stored type decides. A token for no file stays as typed; a file with no token is added as above (an image's embed at the end, another file only listed). Without `place` (or with no files) nothing is a token: text that looks like one is kept as sent, as it always was. The page's `title` is the first line of `text` with words (with `place`, its tokens left out), without a leading Markdown heading marker (`#` to `######` and a space), at most 200 characters; else the `url`; else `created_at` as `YYYY-MM-DD HH:MM`, in the offset it was sent with (UTC if it was not sent). The slug is made from that title once and stays when the title is edited (see [](../explanations/architecture/data-model.md)); Claude may replace the title of a photo with no text (with `place`, tokens alone are no text: the capture's `text` is then `null`), or of a saved link, with its own. `422` also for an `id` that is not a ULID, a `created_at` that is not ISO 8601, a capture with no text, url or file, a request that is neither JSON nor `multipart/form-data`, and a JSON body that is not an object. Returns `{capture_id, page_id, slug}`. `413` over the upload limit; `422` if the page's text (the `url` and `text`) is over 1 MB of UTF-8, before any file is kept. Files are stored as sent (HEIC too) |
| `GET /api/pages?limit=50&kind=` | Pages, most recently changed first (by their text: a kind or `fields` change doesn't count); the trash is left out. `limit` is 1 to 500 (default 50; `422` outside). `kind=todo` lists only that kind (`note`, `todo`, `consume`, `whiteboard` or `document`; another is `422`; empty means all). Each has `id`, `slug`, `title`, `kind`, `kind_fixed`, `fields`, `created_at`, `updated_at`, `tasks`, and a todo's `due` and `priority` (`null` on other kinds); `thumb` is the SHA-256 of the page's first image, or `null` |
| `GET /api/pages/{id or slug}` | A page with `rev` (its current revision), `tags` (most used first), `removed` (the SHA-256s of files an earlier revision's text referred to and the current text does not: the PWA no longer lists them), and its captures, each with its files as `blobs` (see {ref}`the page object <api-page-object>`, which also lists `model_tags`, `related` and `enrich`). Each file (`{sha256, mime, size, filename, ingest}`) of a photo has `ingest`: `null` if it was never queued, else `{state, failures, error, text, description, image_kind, drawing}` (`drawing`: `null`, or the current version's `{id, version, producer, width, height}`), `state` being `queued`, `processing`, `done`, `failed` or `paused` (see [](../explanations/ingest.md)). A PDF or text file (`text/plain`, `text/markdown`), whose text scrap reads itself for search (no model), has instead `ingest`: `null` if it was never queued (a file attached before scrap read files: `POST /api/captures/{id}/reprocess` queues it), else `{state, failures, error, kind, pages, pages_read, truncated, text_chars, searchable}`: `state` `queued`, `processing`, `done` or `failed` (never `paused`: a pause does not hold a file), `error` the reason it failed (for example `content: the PDF could not be read`, `too large: 41 MB, over the 30 MB limit`, `timeout: ...`), `kind` `pdf` or `text`, `pages` and `pages_read` a PDF's page count and how many were read (`null` until it is read, and for a text file), `truncated` whether the text was cut (at the first 200 pages or 500,000 characters), `text_chars` the length of the text kept and `searchable` whether there is any (`false` for a scan with no text layer). | `POST /api/pages/{id or slug}/captures` | Add photos or files to a page that exists: the page editor's **Add photo**. `multipart/form-data` with `id` (a ULID minted by the client: the retry key, as for `POST /api/captures`), one or more `file` parts, all images, PDFs, or text or Markdown files (`text/plain`, `text/markdown`; typed as for a capture, so an untyped `.md` or `.txt` is typed by its name), and `source?` and `created_at?` as for a capture; `415` for any other file, and nothing is saved. The files become a capture of the page, received now, so they come after the page's own (captures are in the order the server received them): a `photo` capture if any of them is an image (its images are sent to Claude as Add photo's always were, and a file among them is read as a file), else a `file` capture. A PDF or text file is not put in the text: the page lists it below, and its text is read for search as a capture's is (see [](../explanations/ingest.md)). For each image the text does not show already, `![](/api/blobs/<sha256>/preview?size=2048)` is added to the end of `body` as it is now, all in one new revision by the caller (none if there is nothing to add, as when only files are added). No revision is checked (a `base_rev` sent is ignored): appending loses nothing. The photos are queued for Claude as a capture's are, and are read and searched, but never change the page's kind, title or tags, nor whether enrich or ingest maintains it: a page's first capture decides that (see [](../explanations/ingest.md)). `404` for an unknown page or one in the trash; `422` for a topic page (its synthesis is its write-up, which a board photo would replace), an `id` that is not a ULID or is another page's capture, no file, a bad `source` or `created_at`, a request that is not `multipart/form-data`, or a `body` that would be over 1 MB; `413` over the upload limit. Returns the page (as `GET` does) with `appended_on`, the revision the embeds went onto (the page's revision before, so a client holding it can take them into its own text; `null` when no image was added): `201`, or `200` with the page as it is now and `appended_on` `null` on a retry with the same `id` |
| `PATCH /api/pages/{id or slug}` | `{base_rev?, title?, body?, kind?, fields?, tags?, tags_shown?, due?, priority?}`. A `title` or `body` writes a new revision and needs `base_rev`: `409` with the current `rev` if it is stale (and nothing in the request is saved). A `title` has runs of whitespace collapsed to single spaces; one that is empty or only whitespace is `422` (`title must not be empty`) and nothing in the request is saved. A `title` equal to the title at `base_rev` counts as unchanged, so it never undoes a title Claude set meanwhile. The slug does not change with the title. `kind` (as for a capture) sets `kind_fixed` (ingest then never changes it); a different kind keeps every field the page has and adds that kind's defaults for keys it lacks: `todo` `{"status": "open"}`, `consume` `{"subtype": "read", "status": "open", "source"}` (`source`: the capture's URL, if any). A default is added only if the page has room (at most 32 fields): a page with 31 fields gets one of them, a full one none, and a field the page has is never dropped for it (so the change is not a `422`). So nothing is lost by changing a kind and back; a `status` already there keeps its value. `fields` changes them, e.g. `{"status": "done"}` ticks a todo; a `null` value removes one; names are 1 to 40 characters, values flat (a string of at most 200 characters, a number or a boolean; a whole number is within ±2^53 and any other finite, so `NaN`, `Infinity` and `1e400` are `422`), and a page has at most 32 fields (`422` otherwise). `tags` replaces all the page's tags (`[]` removes them), each cleaned as an import's are (one space between words, no leading `#`, lower case, 1 to 64 characters, each once; at most 64 tags, `422` otherwise). A tag Claude added that is not in `tags` is taken off for good (Claude never adds it back); with `tags_shown`, the tags the editor started from (the PWA sends them), one Claude added that is in neither list is kept instead, since the user never saw it. `due` (a date, `YYYY-MM-DD`: no time, no time zone) and `priority` (`high`, `medium` or `low`) are a todo's own values, not fields (a `snoozed_until` sent is ignored: Snooze was retired): sent, they set it, `null` clears it, not sent keeps it; a value is `422` on a page of another kind (after any `kind` in the same request: `{"kind": "todo", "due": ...}` works), as is a malformed one. A page that stops being a todo keeps them (a stray tap loses nothing), but they are ignored, and returned as `null`, until it is one again. Neither `kind`, `fields`, `tags`, `due` nor `priority` is a text revision, nor changes `updated_at`; a change of `kind` or `tags` is a metadata revision (`page_meta_rev`: who, kind and tags before and after; see [](mcp.md)), as Claude's are, so it can be seen and reverted over MCP. A `body` (here, in a capture or over MCP) is counted for its task boxes, `tasks: {done, total}` on the page and its rows (exactly as the PWA draws them: a list item whose first line starts `[ ]` or `[x]` as typed; none in code, escaped `\[ ]`, or a link named `[x]`): a `note` whose kind nobody chose (`kind_fixed` 0: no `kind` was ever sent for it; the PWA sends one only when the user picks a kind, never for boxes) that has boxes becomes a `todo`, filed as a new capture of that text would be (all ticked: `done`); a todo's `status` becomes `done` when the last box is ticked, and, on a done one whose boxes were all ticked, `open` again when one is unticked or a new unticked one is added (a todo marked done by hand with some boxes unticked stays done); never on a `cancelled` one; a status set by hand ticks no box, and a `fields.status` in the same request as the `body` is kept, whatever its boxes. A `body` over 1 MB (1,000,000 bytes) of UTF-8 is `422` (a page's text is at most that, however it is written; nothing in the request is saved), unless it is exactly the page's current body, so a page imported over the limit can still be retitled, retagged or given another kind. With files (the page editor's Camera, Gallery and File), the request is `multipart/form-data`: the edit as JSON in an `edit` part (with `body` and `base_rev`), and `file` parts, images, PDFs and text or Markdown files only (`415` otherwise; an untyped part is typed by its name), within the upload limit (`413`). Each `⟦image N⟧` or `⟦file N⟧` (also `⟦file N: name⟧`) in `body` becomes the Nth file's embed (`![](/api/blobs/<sha256>/preview?size=2048)`) or link (`[name](/api/blobs/<sha256>)`), as a capture's tokens do with `place`, and the files are recorded on the page as a new capture (a `photo` capture if any is an image, so its images are read by Claude as Add photo's are, else a `file` capture; PDFs and text files are read for search), in the same revision as the text. A stale `base_rev` is `409` and records no file. Returns the page |

(api-cli-status)=
### Exit status and common errors

A command that works exits `0`. One that refuses prints a single line on stderr and exits `1`.
Arguments it cannot use (`scrap enrich` with none or more than one of `--backfill`, `--related`,
`--writeups` and `--topics`, or `--outdated` without `--writeups`, an unknown option) print the
usage and exit `2`. `scrap` alone prints the help and exits `0`.

`scrap serve`, `restore` and `enrich` (every mode) create the data folder and bring `scrap.db` up to
date. `backup`, `export`
and `gc` never create or upgrade anything: with no `scrap.db` they stop at once. That makes
a wrong `--data-dir` easy to miss. With no `--data-dir` and no `SCRAP_DATA_DIR` the data folder is
`./data` under the current directory, so run from the wrong place, `serve` and `enrich`
quietly start a new empty one, while `backup`, `export` and `gc` say `no database at
data/scrap.db`.

| Message | Cause |
| --- | --- |
| `no database at <data folder>/scrap.db` (`scrap gc: no database at ...` for `gc`) | `backup`, `export` or `gc` was pointed at a folder with no database: the wrong `--data-dir`, or the working directory is not the one you expected |
| `scrap gc: no files folder at <data folder>/files` | The database is there but the data folder has no `files/` |
| `scrap gc: the grace period must not be negative` | A negative `--grace-hours` |
| `scrap gc: the run retention must be at least 1 day` | A `--run-days` below 1 |
| `scrap gc: the trash retention must be at least 1 day`, `scrap gc: the job retention must be at least 1 day` | A `--trash-days` or `--job-days` below 1 |
| `scrap gc: the run retention must be at most 36500 days` (or `trash`, `job`) | A `--run-days`, `--trash-days` or `--job-days` over 36500 (a hundred years) |
| `scrap gc: cannot purge the trash or prune old records, so nothing was deleted: ...` | The database refused the purge (read-only, disk full); nothing changed |
| `scrap gc: cannot read what is in use, so nothing was deleted: ...` | The database could not be read, or it is newer than this scrap |
| `scrap gc: cannot put back a file left aside by an earlier run, so nothing was deleted: ...` | A file an earlier run set aside could not be restored (permissions or disk) |
| `scrap gc: another scrap gc is deleting (it holds <data folder>/gc.lock); ...` | Another `--delete` run is in progress, such as the nightly one; try again when it ends. Counting runs take no lock |
| `no backup at <DIR>` | `scrap restore`'s `DIR` has no `scrap.db` |
| `bad backup: ...` | The backup's database is not a database, fails its integrity check, or has a schema newer than this scrap. The data folder is left as it was |
| `<data folder> is not empty; stop scrap and use --force` | `scrap restore` into a data folder that has a database or any file; see `--force` above |
| `stopped: the queue is paused (<reason>)` | `scrap enrich --related`, `--writeups` or `--topics` met a pause or spent the day's budget (exit `1`) |

A setting scrap cannot use stops it with its own message: see {ref}`api-settings`.

(api-cli-folders)=
### Backup and export folders

`scrap backup DIR` makes `DIR` if it is missing, then replaces `DIR/scrap.db` with a fresh snapshot
(written as `scrap.db.part` and renamed, so a run that stops half way leaves the earlier database
whole) and copies `files/` (laid out as in the data folder, `files/<first two hex digits>/<sha256>`).
Files are only ever added: one already in `DIR/files/` is neither touched nor removed, and names that
start with `.` (uploads in flight) are skipped. The preview cache (`cache/previews/` in the data
folder) is not copied. So backing up again into the same `DIR` is incremental, and `DIR` goes on
holding files no page uses any more (after a `scrap gc`, say). Use a new `DIR` for each backup if
that matters; the single-server timer does, and keeps the newest `SCRAP_BACKUP_KEEP` of them (see
{ref}`scrap-backup-restore`).

`scrap export DIR` writes one `<slug>.md` per page at the top of `DIR` and one `DIR/files/` for all
the pages, in which a file is named `<sha256><extension>`, the extension being the usual one for its
content type (none if it has none). It is not the name it was uploaded under, and a file on several
pages is stored once. A photo's drawing is `<sha256>-<capture id>.excalidraw`, since a drawing
belongs to a capture. The page download names files differently (by their uploaded names: see
`GET /api/pages/{id or slug}/download`).

Run it again into the same `DIR` and every `.md` and drawing is written afresh, while a stored file
already there is left alone. Nothing is deleted: a page put in the trash since, and its `.md`, stay in
`DIR`. Export into a new folder for a clean copy.

(api-settings)=
## Settings

The settings are environment variables of the service, read at start. A setting that is on or off
(`SCRAP_INGEST`, `SCRAP_ENRICH`) is on for `on`, `1`, `true` or `yes`, in any case; anything else
is off. The variables below are scrap's own; those that install scrap (the image, where it
listens, the data and backup folders) are in [](../how-to/deploy-single-server.md), and the
chart's values in [](../how-to/deploy-kubernetes.md).

| Variable | Default | Meaning |
| --- | --- | --- |
| `SCRAP_DATA_DIR` | `./data` | The data folder |
| `SCRAP_WEB_DIR` | the packaged PWA | Serve the PWA from this folder instead: a new build there shows without a restart |
| `SCRAP_PUBLIC_URL` | unset | The address the service is reached at, e.g. `https://host.tailnet.ts.net:8446` (several, comma separated). Every route but `/healthz` answers only requests whose `Host` is loopback or one of these, or (except on `/mcp`) an IP address, and a write only an `Origin` that is (DNS rebinding and cross-site protection; see [Host and Origin](#host-and-origin)), and the first makes the page URLs MCP tools return; without it they are paths (`/p/<slug>`). A Markdown link to `/p/<slug>` on any of them is a page link (links, backlinks, `is:orphan`, `has:dangling`), and the PWA opens it in place: the server lists their origins in the `index.html` it serves (`<meta name="scrap-origins">`). An installed app keeps that page offline, so it picks up a changed list on its next app update; the address it was opened at always works. An address without a scheme and host (`foo`) stops scrap at start with `SCRAP_PUBLIC_URL: 'foo' is not a URL`; see [](mcp.md) |
| `SCRAP_MCP_TOKEN` | unset | Bearer token(s) `/mcp` requires, comma separated. Unset (with `SCRAP_MCP_TOKEN_FILE` also unset): `/mcp` is open as before. Only `/mcp` is guarded; `/healthz`, the API and the PWA are not. A set but empty value stops scrap at start. See [](mcp.md) |
| `SCRAP_MCP_TOKEN_FILE` | unset | A file with one bearer token per line (blank lines and `#` comments skipped), for a mounted secret; its tokens add to `SCRAP_MCP_TOKEN`'s. A missing or token-less file stops scrap at start |
| `SCRAP_IDENTITY_HEADER` | `Tailscale-User-Login` | The request header recorded as the author of a change, else `tagged`. Only this header is read; set it to what your authenticating proxy sends (e.g. `X-Auth-Request-User`). Blank counts as unset, and so does a value of `claude` (any case), MCP's author |
| `SCRAP_REVISION_WINDOW` | `300` | Seconds within which one author's changes to a page's kind and tags fold into one metadata revision, and one author's text edits from one source (Claude's over MCP) into one text revision; `0`: each change is one. A value that is not a number of at least 0 stops scrap at start |
| `SCRAP_MCP_CONTENT_EDIT` | `1` | `0` (or `false`, `no`, `off`): MCP does not offer `edit_page`, `edit_drawing`, `trash_pages` or `undelete`, and refuses `revert` with `to_rev`, so no MCP session can change the text of a page it did not write (see [](mcp.md)). Unset is on; any other value, empty too, stops scrap starting |
| `SCRAP_MAX_UPLOAD_MB` | `50` | Largest request body (a capture's files together), enforced as it arrives: `413`. May be fractional; a value that is not a number stops scrap at start. `/mcp` has its own fixed cap of 2 MB |
| `SCRAP_TRASH_DAYS` | `30` | How long a page stays in the trash (1 to 36500 days, or `off`) before the nightly `scrap gc` purges it, as the server shows it (`GET /api/trash`, the PWA's Trash, the MCP `trash` tool and instructions). Set it to the `--trash-days` the gc runs with (the chart does, from `gc.trashDays`); `off` when no gc purges the trash, so no date is shown. A number below 1, or anything else, stops scrap at start. It does not purge anything itself |
| `SCRAP_INGEST` | `off` | `on` starts the worker that sends photos to Claude and reads PDFs' and text files' text for search, locally (both are queued either way: with it off, files wait unread, as photos do) |
| `ANTHROPIC_API_KEY` | | The key for the Claude API; keep it in the service user's mode-600 env file |
| `SCRAP_LLM_BACKEND` | `api` | `api`: the Messages API with `ANTHROPIC_API_KEY`. `cli`: Claude Code (`claude -p`) on a Claude seat, with `CLAUDE_CODE_OAUTH_TOKEN`; needs the `claude` binary (`Dockerfile.claude`). See [ADR 0021](../explanations/decisions/0021-ingest-on-a-claude-seat-through-claude-p.md) |
| `CLAUDE_CODE_OAUTH_TOKEN` | | With `SCRAP_LLM_BACKEND=cli`: the seat token from `claude setup-token`; mode-600 env file only, it can use the whole seat |
| `SCRAP_VISION_MODEL` | `claude-opus-5-5` | The model photos are sent to. Empty counts as unset. A name the API does not know is a `404`, which pauses the queue as `auth` until *Resume* (see {ref}`ingest-spend`). The effort of the photo call is fixed at `medium`; no setting changes it |
| `SCRAP_ENRICH` | `on` | With ingest on, Claude also tags, summarises and links text pages and fetches saved links; `off` keeps it to photos |
| `SCRAP_FILE_ENRICH` | `auto` | `auto`: with ingest and enrich on, a page made from a PDF or text file (its first capture a file capture, not an import) is titled, tagged, summarised and related once its files are read, sent the start of their text (at most 4,000 characters to enrich, 1,500 to related; never the file), on the text model, the shared budget and pause. `ask`: a file's text goes to Claude only on *Ask Claude*. Ask works either way; `SCRAP_ENRICH=off` stops both. Case-insensitive, empty counts as unset; any other value stops scrap at start when `SCRAP_INGEST` is on. See [ADR 38](../explanations/decisions/0038-file-text-is-sent-to-claude-on-capture-bounded.md) |
| `SCRAP_TEXT_MODEL`, `SCRAP_TEXT_EFFORT` | `claude-haiku-5-5`, `low` | The model and effort for text pages. Empty counts as unset. Both go to the API as given, with no check: a model it does not know pauses the queue as `auth`, and an effort it rejects is a `400`, class `content`, which fails every text job (each charged; the third failure of a job ends it, and *Ask Claude* retries) |
| `SCRAP_ENRICH_DEBOUNCE` | `60` | Seconds after a note's capture or save before Claude reads it (later saves move it). A value that is not a number means `60`; a negative one means `0` (no wait) |
| `SCRAP_BUDGET_DAY_USD` | `3` | Daily spend, from recorded usage, after which the queue pauses until UTC midnight. A number of dollars, fractions allowed; `0` pauses the queue at the first job it claims. A value that is not a number stops scrap at start when `SCRAP_INGEST` is on, and `scrap enrich --related` when it runs, with a Python `ValueError` traceback rather than a message; with ingest off the value is never read. With `cli`, the CLI's notional cost at API prices |
| `SCRAP_NOTIFY_URL` | unset | If set, the first pause of an episode POSTs one fixed line naming its reason here (an ntfy topic works), and so does `scrap gc --delete` when it starts a month's *Orphaned assets* page (where it has network: not the single server's gc container) |
| `TZ` | the host's; `UTC` in the image | The server's time zone, e.g. `Europe/London`. It decides what "today" is for the search filters `due:today`, `due:tomorrow` and `due:yesterday`. The image has the tz database, so the setting works there |
