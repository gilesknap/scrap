MCP server and access#

scrap has no login of its own. The network in front is the gate, the identity header says who did a thing, and /mcp adds an optional bearer token for clients that come in from outside.

Three ways in#

Every route ends at the same FastAPI app. What differs is the gate in front, where the author is attributed and where the bearer token is checked.

  • Unix socket. scrap serve --uds PATH binds a socket mode 600 in a folder that must be mode 700 and owned by the user (uds.py). Root and anything running as the scrap user can still open it and forge the header, so run scrap as its own user (ADR 0018).

  • Loopback TCP. SCRAP_LISTEN=tcp publishes 127.0.0.1:$SCRAP_PORT (default 8790). It is opt-in for new installs, but deploy/scrap-run treats an unset SCRAP_LISTEN as tcp, so env files from before the socket keep working. Any local process can reach it and send any Tailscale-User-Login. Bare scrap serve listens on 127.0.0.1:8000 with the same caveat.

  • Kubernetes. networkPolicy.enabled (off by default) admits only the networkPolicy.from peers on the http port, or nothing when the list is empty. The ServiceAccount does not mount its token (automountServiceAccountToken: false).

Chart defaults leave the cluster open#

The chart’s defaults favour a first install that works over safe-by-default: mcp.tokenSecret is empty, so /mcp needs no token, and networkPolicy.enabled is false, so any pod in the cluster can reach the whole API and /mcp and send any identity header. (The Host and Origin checks stop other web pages, not other pods.) Where other workloads share the cluster, set:

mcp:
  tokenSecret:
    name: scrap-mcp-token      # an existing Secret; the key holds the bearer token
    key: SCRAP_MCP_TOKEN
networkPolicy:
  enabled: true
  from:                        # only the proxy that fronts scrap
    - namespaceSelector:
        matchLabels:
          kubernetes.io/metadata.name: tailscale

and set SCRAP_PUBLIC_URL to the address you reach scrap at. The token guards /mcp only; the NetworkPolicy is what keeps other pods off the API. See Deploy on Kubernetes.

Identity is attribution, not the gate#

  • author is the request header named by SCRAP_IDENTITY_HEADER (default Tailscale-User-Login). Without it the author is tagged: tagged tailnet devices send none.

  • Only the configured header is trusted. A proxy that sets another one (for example X-Auth-Request-User) is named in that variable.

  • MCP changes are always authored claude from source mcp, whatever the caller; is:claude (pages made_by claude) and is:claude-edited (text revisions from source mcp) find them. A web request is always source web, and a header value of claude counts as no header, so no request can pass for Claude (ADR 33).

  • The header is trusted as sent. scrap does not check that the proxy set it, so a client that reaches scrap by any other path (a port-forward, a NodePort, another pod in the cluster, an ingress that does not strip it) chooses its own author name. It can name nobody as Claude, but the attribution is then worthless. Strip the header at every ingress that is not the identity proxy, and make the proxy the only way in.

  • The ACL is the gate. Tagged servers, such as any internet-facing box, must not be granted access to the scrap device (ADR 0007).

The MCP server#

/mcp is served by the official MCP SDK inside the app (Streamable HTTP, stateless, JSON replies), so one claude mcp add --transport http line connects a client and a restart drops no session (ADR 0013). There are fifteen tools; arguments, limits and result shapes are in MCP server.

One write#

An MCP edit is a revision recorded under the author claude and source mcp, so a person can see it and undo it.

        sequenceDiagram
    autonumber
    participant C as Claude client
    participant P as Proxy / Serve
    participant B as /mcp bearer check
    participant T as Tool
    participant S as Store
    C->>P: POST /mcp (Bearer token)
    P->>B: forward, Host and Origin intact
    B-->>C: 401 if token missing or wrong
    B->>T: edit_page(page, old, new)
    T->>S: write text, new page_rev (author claude)
    S-->>T: rev id
    T-->>C: result with PWA link and rev
    Note over C,S: revert(page, to_rev) restores earlier text as another revision

  • The bearer check runs first, ahead of the Host and Origin checks and every tool; only /mcp is guarded. Tokens (SCRAP_MCP_TOKEN, comma separated, or SCRAP_MCP_TOKEN_FILE, one per line) compare in constant time and are never logged. A setting that yields no token stops startup rather than leaving /mcp open.

  • Then the transport checks Host and Origin against loopback and SCRAP_PUBLIC_URL (DNS rebinding protection). Set it to the Serve address or clients get 421 or 403.

  • The web app and the API (every route but /mcp and /healthz) check Host and, on writes, Origin the same way (hostguard.py, #238), so another site cannot write through the owner’s browser.

  • Limits per write: body 200 000 bytes, 20 tags, 200-character title, 200 pages per bulk edit_meta, request 2 MB.

Untrusted content#

Pages, imported notes and fetched links are data, never instructions. Two boundaries keep it so.

        flowchart TD
    IN["Page text<br/>fetched link"] --> F["fetch.py<br/>public addresses only"]
    F --> PR["Claude call<br/>fixed prompt, no tools"]
    IN --> PR
    PR -->|"JSON schema"| SAN["sanitise.py"]
    SAN --> ST[("Store<br/>model fields only")]
    ST --> OUT["MCP result<br/>quoted JSON fields"]
    OUT --> CL["MCP client<br/>treats as data"]
    classDef store fill:#e8f1ff,stroke:#4a7bd0
    classDef claude fill:#fff3e0,stroke:#e08a00
    classDef user fill:#e9f7ef,stroke:#2e9d5b
    class ST store
    class PR,CL claude
    class IN user

  • Inbound. scrap calls Claude with a fixed prompt, no tools and a JSON schema, so there is nothing to call, no file to read and no shell. Output is checked and sanitised (sanitise.py) and the user’s text is never edited. The worst case is a wrong title, tag, kind or summary, which page_meta_rev and page_rev undo.

  • Fetching. fetch.py refuses private, loopback, tailnet and metadata addresses. It checks the address after DNS resolution and again at every redirect, then connects to the address it checked, with size and time limits.

  • Outbound. Tool results return page text in JSON fields, and the server instructions tell the client it is the user’s data, quoted. edit_page and revert are for pages the user asked to change, with dry_run available.

  • Holds. The database, files and the Claude API key; no cluster or git credentials and no shell tools.

  • The content-edit tradeoff. SCRAP_MCP_CONTENT_EDIT is on by default, so an MCP client holds edit_page, revert, bulk edit_meta and trash_pages next to read. A page you captured (a web clip, an imported note) may contain text written to talk a model into using them, and the only defence is the instruction not to act on page text, which a model can still fail. The damage is bounded: every edit is a revision, revert undoes it, and trashed pages stay recoverable for 30 days. If you read pages you do not trust in a session with these tools, set SCRAP_MCP_CONTENT_EDIT=0 (the edit tools are then not listed at all).

  • Reading is not acting. A session that holds cluster or other powerful credentials should not mount the scrap MCP server, since pages may contain injected text.
