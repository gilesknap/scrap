Public site#

The contract for public pages: what the PWA uploads to scrap, what scrap pushes to the public site’s receiver, and how nginx serves it. This page is the single source of truth for it; the scrap-public image and scrap both follow it. Why it is built this way is in 43. Public pages: a static site scrap pushes to.

scrap is the receiver’s only client. The PWA never talks to the receiver, and the receiver is never on a public ingress: only nginx is.

Transport and auth#

  • HTTP/1.1 with keep-alive. Receiving a request, its headers and body, has 30 seconds (408); the fsync and swap after it are not counted.

  • A client should send Expect: 100-continue with every request that has a body, where the client library supports it, so a refusal that needs only the headers (401, 411, 413, 415, 422 bad_unit, and 503 busy, since the write lock is tried from the headers before 100 Continue) arrives before the body is sent. When the receiver refuses a body it has not read, it closes the connection lingering (it reads and drops what is still arriving for a moment first), so a client that cannot send Expect still sees the answer rather than a reset.

  • Every route except GET /healthz needs Authorization: Bearer <token>, compared with hmac.compare_digest. Without it the answer is 401 with WWW-Authenticate: Bearer, before any other check: an unknown path is 401 too, not 404. The token, and the Authorization header, are never logged; the log has the request line and status only.

  • Every error is JSON, {"error": "<code>", "detail": "<a sentence>"} (Errors).

  • A wrong method on a known route is 405 with Allow.

The tar#

A unit’s body is a tar:

  • uncompressed, in pax or ustar format;

  • of regular files only (REGTYPE): a directory entry, symlink, hard link, device or FIFO is refused (422 bad_member); a GNU tar member type or a sparse member is refused as 400 bad_tar;

  • with relative paths and no ./ prefix: 1 to 4 segments joined by /, each matching [A-Za-z0-9_][A-Za-z0-9._-]{0,99} (so no leading ., no .., no absolute path), within the unit’s own rule above;

  • each path once, and no path that is also a folder of another (a and a/b.html);

  • not empty (422 empty_unit);

  • with no pax extended header, or GNU long-name or long-link header, over 64 KiB (400 bad_tar).

The extension is what follows the last . of the last segment, compared in lower case. The receiver reads the tar member by member as it streams in, writing each file itself; it never uses extractall. Any refusal leaves the site as it was.

The digest#

Every PUT carries Scrap-Digest: <64 lower-case hex>: the SHA-256 of, for each file in sorted path order (byte order; paths are ASCII), the line

<path> NUL <hex sha256 of the file's content> LF

concatenated. In Python:

hashlib.sha256(b"".join(
    p.encode() + b"\0" + hashlib.sha256(files[p]).hexdigest().encode() + b"\n"
    for p in sorted(files)
)).hexdigest()

The receiver computes it again from the tar. A missing or different digest is 400 digest_mismatch, and nothing changes. It is also the unit’s digest in the manifest.

Endpoints#

GET /healthz#

No token. Always 200 {"ok": true} while the receiver runs.

GET /v1/manifest#

200 with what the site holds:

{
  "version": 1,
  "bytes": 12345678,
  "quota": 2147483648,
  "units": {
    "p/my-whiteboard": {"digest": "<hex>", "files": 3, "bytes": 812345, "at": "2026-10-31T14:02:11Z"},
    "home": {"digest": "<hex>", "files": 3, "bytes": 20480, "at": "2026-10-31T14:02:12Z"}
  }
}

bytes (the site’s and each unit’s) is the files’ actual content in bytes; only the quota counts in 4 KiB blocks (Limits). quota is the limit, and at when the unit was last written (UTC, ISO 8601, to the second).

PUT /v1/units/{unit}#

Replace a unit, or make it. Required: Content-Type: application/x-tar (415 unsupported_media_type), Content-Length (411 length_required; a chunked body is 411 too, and a length that is not a number 400 bad_request) and Scrap-Digest. Send Expect: 100-continue where the client supports it (Transport and auth).

One lock serialises every write (PUT, DELETE, sync). It is tried as soon as the headers are in, before 100 Continue; a request that cannot take it at once gets 503 busy with Retry-After: 1, before any body is sent.

The swap is atomic, so nginx serves the old unit or the new one, never a mix or nothing: the files are unpacked into staging/<id>/ and fsynced, moved to units/<id>/ with the unit’s manifest entry beside it, then a new symlink at www/<unit> replaces the old one with os.replace, and the old copy is deleted.

200 with the unit’s manifest entry and "unit". Other answers: 400 bad_tar, 400 short_body (fewer bytes than Content-Length), 400 digest_mismatch, 422 bad_member, 422 no_index, 422 empty_unit, 413, 507, 408.

DELETE /v1/units/{unit}#

Remove a unit. 204, also when it was not there, or 503 busy.

POST /v1/sync#

{"keep": ["home", "pagefind", "assets", "p/a", "t/b", ...]} deletes every live unit not in the list. It needs Content-Type: application/json (415) and Content-Length (411), with a body of at most 1 MiB. 200 {"deleted": [...]}. Refused: a body that is not {"keep": [strings]} (400 bad_request), an empty list (422 empty_keep), a list without home (422 no_home), and an entry that is not a unit (422 bad_unit).

The site folder#

RECEIVER_SITE holds:

  • www/: nginx’s root, holding only each unit’s symlink (www/p/<slug>, www/t/<key>, www/home, www/pagefind, www/assets) to its copy;

  • units/<id>/ and units/<id>.json: each unit’s files and its manifest entry;

  • staging/: uploads being unpacked.

units/ and staging/ are outside nginx’s root, so they are never served. At start the receiver empties staging/, rebuilds its index of live units from the symlinks, and removes every copy no symlink refers to and anything else in www/. In Kubernetes the folder is an emptyDir: a restarted pod starts empty and scrap fills it again (Reconciling).

nginx#

nginx serves www/ read only, as files. It takes GET and HEAD only (405 otherwise), with autoindex off and server_tokens off.

Caching#

  • HTML: Cache-Control: no-cache, so a browser or proxy checks again before each use, and an unpublished page is gone on its next load.

  • Every other file: Cache-Control: public, max-age=300, so a deleted file can be seen from a cache for up to five minutes more.

Nothing the site does reaches copies people saved, or caches that ignore these headers.

What the publish mode writes#

pagehtml.ts has a publish mode beside Share as HTML. It reads the page as the PWA shows it and writes one HTML file, which scrap then checks (What scrap sends for a page). The design of the PWA’s side (the toggle, the badge, the dialogs) is on the sim’s design branch, design/497-public-pages.

Marked default below: a choice the owner may still change, kept in one place so it is easy to change.

Included

  • The body as shown, Claude’s write-up and Claude’s summary.

  • The tags, as chips: <a href="scrap-tag:<tag, URL-encoded>">, which scrap turns into /t/<key> (Tag keys).

  • Linked from and Related (the links scrap adds itself): an entry is kept only if the other page is public. Otherwise the whole entry, its title included, is dropped.

  • Maths, as katex.renderToString writes it (KaTeX's markup).

  • Mermaid diagrams as their source, in <pre><code class="language-mermaid">, not rendered.

  • Heading and footnote ids, so #... links within the page work.

Links

  • To a public page: <a href="/p/<slug>">, which works on the site as it does in scrap.

  • To a private page: a plain <span> holding the label the owner typed. With no typed label (a bare [[slug]], or a bare /p/<slug> address) the text is “a private page”, never the slug. Default.

  • Elsewhere: http: and https: links as written, within the link rules.

Images and files

  • An image: <img src="scrap-blob:<sha>" alt="...">. The alt is the text the owner typed in Markdown (![alt](...)). An alt the PWA filled in from the file name is written as alt="": a file name is never published as alt text. Default.

  • A file: <a href="scrap-blob:<sha>"> with the link’s label.

  • Drawings (Excalidraw) are not published in this version: they are left out, and a photo with a drawing on it is published as the photo alone. Publishing drawings is a follow-up.

Left out: Claude’s notes on a photo (its description, the read text, its drawing), drawings, revisions, the extracted text of files, the PWA’s controls, and every /api or other private address.

Head: the fixed meta CSP, /assets/page.css, and /assets/katex.css for a page with maths (The HTML scrap accepts).

The PWA’s dialogs (the sim’s wording on the design branch is the final text):

  • Turning Public on asks once, OK or Cancel, saying that anyone with the address can read the page, and that its tags and Claude’s write-up and summary go public with it.

  • A save of a public page while offline is saved but not published, with the toast “Saved. Not published while offline: Refresh all public pages in Settings later.” Publishes are never queued.

  • Refresh all asks first when any public page has never been published (made public over MCP, say, or restored): it lists them and asks once, “These pages will go public for the first time: … OK / Cancel”. Pages already published are refreshed without asking. Default.

The PWA’s API in scrap#

These routes are under /api, so only the owner’s PWA session reaches them (behind Cloudflare Access or Tailscale, as the rest of /api). They are not served under /mcp, and an MCP bearer token cannot reach them: MCP never publishes HTML. Errors are scrap’s usual {"error", "detail"} JSON. {key} is a page’s id or slug, as elsewhere in the API.

The flag#

PATCH /api/pages/{key} with {"public": true} or {"public": false}, or MCP edit_meta(public=...), sets page.public, as a revision that revert can undo. Making pages private works in bulk through the same routes; public: true for more than one page in one request is refused with 422 one_at_a_time.

  • On only sets the flag. The page is published the next time the PWA renders it: through the Public toggle (which sets the flag, then publishes), a save, or Refresh all.

  • Off unpublishes at once, whichever route turned it off, and so does the page going to the trash. The unpublish runs after the flag change (or the trash) has committed (scrap's copies). If the receiver cannot be reached, the change still succeeds, the answer (200) carries "unpublish": "pending", and the next reconcile finishes the deletion.

  • Undelete and revert keep the flag as it is.

GET /api/pages/{key} includes public (true or false) and published_at. published_at is not a database column: it is read from the kept copy’s meta.json, and is null when there is no kept copy (never published, or unpublished). A page with public on and published_at null shows its badge as “Public · not published yet”. That is only a null timestamp, not stale tracking.

PUT /api/pages/{key}/published#

Publish the page. The body is JSON, at most 25 MiB:

{"html": "<!DOCTYPE html>...", "base_rev": 42, "defer": false}

html is the page from the publish mode, and base_rev the page’s revision the PWA rendered. With defer: true scrap pushes the page’s own unit but not home, the tag units or pagefind (Refresh all, below).

Under scrap’s lock, scrap reads the page again, then checks (What scrap sends for a page), replaces the placeholders, builds the unit and pushes it. 200 with {"url": "<SCRAP_PUBLISH_SITE>/p/<slug>", "published_at": "<UTC ISO 8601>", "files": <n>}.

GET /api/public#

The public pages not in the trash: [{"id", "slug", "title", "published_at"}], with published_at null for a page not published yet. ?links_to=<slug> lists only the public pages whose kept copy refers to that page anywhere: a link in the text, Linked from or Related (the refs in each meta.json). The PWA uses it to decide which links in a page stay live, to find the pages to render again when a page is made public or private, and for Refresh all.

POST /api/public/rebuild#

Build home, every tag unit and pagefind once, and push those whose digest changed: 200 with {"units": [<each unit pushed>]}, or 502 and 503 as for a publish. Refresh all sends each public page with defer: true, then calls this once.

What scrap sends for a page#

scrap checks the uploaded HTML, refusing anything that does not pass with 422 (it never cleans the HTML), replaces its placeholders, adds the page’s files, and pushes the unit.

Parsing#

  • The HTML is parsed with a WHATWG-conformant parser (html5lib in Python), never a regular expression, html.parser or lxml.html, so scrap checks the tree a browser would build.

  • Elements and attributes are matched as (namespace, local name), HTML, MathML or SVG. Anything not listed below is refused, which covers xlink:href, an SVG a and an SVG style.

  • Values are checked after entity decoding. URL rules use re.fullmatch.

  • Comments are dropped or allowed. CDATA sections, processing instructions and template are refused, as is an attribute given twice on one element.

  • “A class includes katex” means katex is one of its whitespace-separated tokens.

  • A style value is parsed as declarations, property: value separated by ;, with spaces after : and a trailing ; allowed.

  • A placeholder (scrap-blob: or scrap-tag:) anywhere but the places allowed below, in text or another attribute, is refused.

The HTML scrap accepts#

The document is <!DOCTYPE html> with html, head, title and body; html, head and body may have only lang and dir. In head, only:

  • <meta charset="utf-8">;

  • <meta name="viewport" content="...">;

  • the CSP, which must be present: <meta http-equiv="Content-Security-Policy" content="default-src 'none'; img-src 'self' data:; style-src 'self'; style-src-attr 'unsafe-inline'; font-src 'self'">. Its parsed content, with whitespace normalised, must equal that exactly. There is no script-src, so no script runs even if the file is opened elsewhere;

  • <link rel="stylesheet" href="/assets/page.css"> (pagehtml’s page CSS, moved out of the file), and, for a page with maths, <link rel="stylesheet" href="/assets/katex.css">. No other link.

There is no <style> element anywhere: every one is refused.

In body, only pagehtml’s kept elements (a abbr article aside b blockquote br caption code dd del details div dl dt em figcaption figure h1 h2 h3 h4 h5 h6 hr i img ins kbd li mark ol p pre q s section small span strong sub summary sup table tbody td tfoot th thead time tr u ul), and, inside a span whose class includes katex (“inside KaTeX” below), KaTeX’s markup:

  • MathML: math semantics annotation mrow mi mn mo mtext mspace msup msub msubsup mfrac msqrt mroot mover munder munderover mtable mtr mtd mstyle mpadded mphantom menclose;

  • SVG: svg, path and line, which it draws stretchy symbols with.

Links scrap accepts#

An a’s href must fully match one of:

  • an absolute http: or https: URL, unless:

    • its host is one of scrap’s own origins (public.public_origins(): the addresses in SCRAP_PUBLIC_URL and the like), compared case-insensitively with a trailing . removed;

    • its path starts with /api/, whatever the host;

    • it has userinfo (user@ or user:pass@ before the host);

  • mailto:..., or #<id>;

  • /p/<slug> of a page that is public, or /t/<key>;

  • a placeholder, scrap-blob:<sha> or scrap-tag:<tag>.

A relative /api/... is always refused, as are //... and /\... (a browser reads both as another host), javascript:, data: and anything else. There is no rule about private (RFC 1918) addresses.

KaTeX’s markup#

The publish mode writes each formula as katex.renderToString(tex, options), with the PWA’s options from web/src/math.ts (trust: false, throwOnError: true, strict: "ignore"), so the markup is KaTeX’s own string, not the browser’s serialisation of the page. The element, attribute and style lists here are derived from KaTeX 0.16.47, the version the PWA bundles: every setAttribute(...) and every .style.<property> = in katex.mjs, checked against both halves (HTML and MathML) of a rendered corpus kept with the check’s tests. The attributes KaTeX sets only with trust (href, src, alt, valign on mglyph) or only for an error it renders instead of throwing (title) are not allowed. A new KaTeX version means deriving the lists again.

position

text-shadow (on span and mstyle)

three lengths

A length is -?([0-9]+|[0-9]*\.[0-9]+)(em|ex|px)?. A colour is # and 3, 4, 6 or 8 hex digits, rgb(...) or rgba(...) of numbers and %, or a name of letters only (red, Goldenrod, transparent). Any other property or value, or style outside KaTeX, is refused.

The katex gate is visual hygiene, not a security boundary. It keeps stray markup and inline styles out of the page’s own content, but a page could wrap anything in a katex span. What keeps a public page safe is the CSP (the page’s meta CSP and nginx’s, with script-src 'none'), the allow-list of elements and attributes, and that the upload is reachable only from the owner’s PWA session.

Placeholders and files#

  • scrap-blob:[0-9a-f]{64} names a stored file by its sha. It is allowed only as the whole value of an img’s src or an a’s href, and must name a file on the page: one referenced in the page’s text, which includes another page’s file the owner embedded. Anything else refuses the publish.

  • scrap-tag:<tag, URL-encoded> is allowed only as an a’s href, and must name one of the page’s current tags (else 422 stale_tags). scrap replaces it with /t/<key> (Tag keys).

What a scrap-blob becomes depends on the stored file, not only on the element:

  • An image is never published as its original. Whichever element names it, scrap publishes its 2048-pixel preview (a raster image) or its sanitised SVG as one img-* file. An img’s src, and an a’s href naming the same image, both point at that img-* file.

  • Any other file named by an a is published as stored, as a file-*. (An img naming a file that is not an image is refused.)

Each becomes an absolute path, /p/<slug>/<name> (absolute, because a relative link from /p/<slug> would resolve under /p/), with the bytes beside index.html:

Stored file

Name

Bytes

A photo or other raster image

img-<n>-<hex>.jpg (.png when its preview is a PNG)

Its 2048-pixel preview, EXIF and GPS stripped when the preview was made

An SVG (an image or an attachment)

The stored SVG, run through scrap’s SVG sanitiser again at publish (SVGs stored before #480 were never sanitised)

Any other file

file-<n>-<hex>.<ext>

The file as stored; <ext> from the list in Units, else bin

  • <n> counts img-* and file-* separately, from 1, in the order they first appear in the HTML; a stored file used more than once is published once.

  • <hex> is the first 10 hex digits of the SHA-256 of the bytes published. Neither the stored sha nor the uploaded file name is published (a link’s label may show the name).

  • Caps: at most 20 images and files together, each at most 20 MiB, and at most 200 MiB for the whole unit (under the receiver’s 256 MiB body). Over any of them scrap refuses the publish with 422 and a message saying which, before pushing anything.

  • Time: the receiver allows 30 seconds to receive a request, so a unit must also be one scrap can upload in that time on its link to the receiver (200 MiB needs about 56 Mbit/s). scrap’s client sends Expect: 100-continue where the client library supports it. A 408 is logged as a failure, and the next reconcile tries the unit again.

Tag keys#

A tag’s key is computed only in Python, by scrap. It is not slug_base, the rule for a page’s slug:

  1. Take the tag as stored. h is the first 8 hex digits of the SHA-256 of its UTF-8 bytes.

  2. Normalise it to Unicode NFKD, encode it as ASCII dropping every character that has no ASCII form, and lower-case it.

  3. Replace each run of characters other than a-z and 0-9 with one -, and strip - from both ends.

  4. Cut it to 60 characters and strip - from the end again.

  5. The key is that slug, -, then h; or h alone if the slug is empty.

So personal/family is personal-family- followed by 8 hex digits (for example personal-family-1a2b3c4d). A key is at most 69 characters, inside the t/ pattern, and two tags with the same slug still get different keys.

What scrap builds#

The derived units are built only from the kept copies and their meta.json (scrap's copies), never from anything else, with plain Python templates and no Markdown:

  • home: index.html (the public pages by published_at, newest first, with their tags and Pagefind’s search box), tags.html (every tag a public page has, with its pages) and 404.html;

  • a t/<key> unit for each tag a public page has: its index.html, listing the tag’s pages;

  • pagefind: the index, built by the pagefind[bin] Python package at a pinned version, plus Pagefind’s UI files and scrap-search.js, which starts the UI. Each page is indexed from an in-memory copy with its .katex elements removed and the formula’s TeX (from its annotation encoding="application/x-tex") put in their place, so search finds the TeX, not KaTeX’s glyph spans;

  • assets: page.css (pagehtml’s page CSS), katex.css and KaTeX’s fonts, from scrap’s own static build of the PWA, and Pagefind’s UI stylesheet, as CSS lives only in assets.

Titles and tag names come from meta.json. Every build is deterministic: the same copies give the same bytes (sorted order, no timestamps), so an unchanged unit has an unchanged digest.

scrap’s copies#

For each published page scrap keeps the unit exactly as it last pushed it, under <data>/cache/publish/p/<slug>/: index.html (placeholders replaced) and every img-* and file-*, with meta.json beside them (not part of the unit):

{"id": "...", "title": "...", "tags": ["..."], "published_at": "<UTC ISO 8601>", "refs": ["<slug>", "..."]}

tags are the page’s tags in the database at publish time; refs the slugs the published page refers to (its links, Linked from and Related), for ?links_to=. It is derived data, not backed up. scrap also stores the digest it last pushed for every unit; a kept copy is damaged when the digest of its files, computed again, differs from that stored digest.

One lock in scrap is held over every publish, unpublish and reconcile step, so they never interleave.

  • Publish: read the page again and refuse unless it is public and not in the trash (409 not_public); check and build the page unit, push it, write the copy, meta.json and the digest; then, unless deferred, build home, the page’s tag units (before and after) and pagefind, and push those whose digest changed.

  • Unpublish (Public off in the PWA or over MCP, a revert, the page going to the trash), after that change has committed: delete scrap’s copy first, then DELETE /v1/units/p/<slug>, then build and push home, the page’s tag units (deleting a tag unit no public page has any more) and pagefind. If the receiver cannot be reached, the copy is still deleted and the next reconcile removes the unit.

Reconciling#

At startup and every 10 minutes, under the lock, scrap:

  1. prunes: deletes the kept copy, and its unit, of every page that is not public or is in the trash, and the kept copy and unit of every damaged copy (scrap's copies);

  2. builds every derived unit fresh (home, every t/*, pagefind, assets) from the kept copies that remain. This also picks up a new KaTeX, new templates or a new Pagefind after an upgrade, and a prune always leads to it;

  3. reads GET /v1/manifest and pushes every unit that is missing or whose digest differs: a page unit from its kept bytes (compared with the digest scrap last pushed and stored), a derived unit from the fresh build. A page’s copy is re-read under the lock before its PUT;

  4. ends with POST /v1/sync listing the units to keep, which deletes any stray.

No rendering is involved, so a site that lost its files (a restarted pod’s emptyDir) is refilled at the next run without the PWA. A page whose damaged copy was pruned comes back at the next Refresh all. A 503 is retried; any other failure is logged and left to the next run.
