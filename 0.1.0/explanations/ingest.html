Claude ingest#

Ingest is how scrap uses Claude. Each photo is sent once for its text, a description, a kind, a title, tags and, for a whiteboard or diagram, an Excalidraw drawing. Notes, todos, reads and saved links get tags, a summary and related pages from a second, cheaper job on the same worker (see Enrich). Every result is a version that can be regenerated, edited or restored, and every call is stored, so a later conversation can start from what the model saw and said.

This page explains how it works and why. It builds on the design. The decisions behind it are 9. Claude ingest: Messages API, no tools, one structured call per photo, 10. Queue error classes: outages pause, charged failures count, spend is capped and 11. Whiteboards become Excalidraw drawings: model skeletons, human scenes, two sanitisers. To switch it on, see Enabling ingest. Every setting is in HTTP API and CLI, the HTTP routes and CLI commands included.

Settled: the Messages API only, on Opus; Reprocess always asks before replacing a human drawing; a daily budget of $3 by default.

Not built: a claude -p backend with a Read tool (one without tools, for Claude seats, is below), a cheaper first-pass model, a monthly budget (the Console spend limit caps it), a circuit breaker and a rate-limit class (the budget and Retry cover them). Chat and refine are not part of ingest yet; the stored runs are kept so they can start from them.

Enabling ingest#

Photos are queued whether or not ingest is on, so nothing captured before you switch it on is lost: it is sent when the worker starts.

The switch is SCRAP_INGEST=on, with ANTHROPIC_API_KEY set (or, on a Claude seat, SCRAP_LLM_BACKEND=cli with CLAUDE_CODE_OAUTH_TOKEN: On a Claude seat (SCRAP_LLM_BACKEND=cli), where a missing token or claude binary pauses the queue at start); the worker does not check the key at start, so a missing or wrong key shows up as failed or paused photos. Where the settings go depends on how scrap is installed:

  • Single server (podman). deploy/install.sh writes ~/.config/scrap/ingest.env (mode 600) and never overwrites it. Uncomment or add the lines there and run systemctl --user restart scrap. The tutorial’s optional last step does this: Install scrap on a server. Every setting is in Ingest settings.

  • Kubernetes (Helm). ingest.enabled, ingest.existingSecret (the chart never takes the key itself) and the optional visionModel, budgetDayUSD and notifyUrlKey: Secrets and ingest.

SCRAP_ENRICH (default on) controls the text-page job and needs ingest on; off keeps ingest to photos. The Helm chart has no value of its own for the text model, effort or debounce, or for SCRAP_ENRICH; set them with extraEnv. It also has no CronJob for the nightly related-pages pass (see Related pages): run scrap enrich --related in the pod yourself, or from a cluster scheduler of your own.

scrap ingest-once IMAGE tries the Claude call on one image file without a database, and prints tokens, cost and counts only; --save FILE also writes the full result. It is the quickest way to check a key and a model.

Worker#

One daemon thread from the FastAPI lifespan. Store is synchronous and SQLite has one writer, so there is no asyncio task and no second process. With SCRAP_INGEST off the thread is not started. The capture transaction enqueues one ingest job per distinct image of a photo capture (Store.ENQUEUE). A unique index, job_one_active, allows one queued or running job per photo, so a repeated photo or a second Reprocess adds nothing.

The thread wakes on an enqueue or every 30 s (POLL) and claims the oldest ready job whose page is not in the trash, with one UPDATE ... RETURNING (ingest.CLAIM), unless the queue is paused (queue_state.paused_until). The claim and pause gate are in one statement, so a pause cannot race a claim.

One job runs at a time, and a photo job is always taken before a text one (see Enrich). It inserts a model_run row, calls Claude holding no lock, then in one BEGIN IMMEDIATE re-reads the job (a purge counts as done), finishes the run, writes the versions and page fields, and marks the job done or applies the error rules below. The loop catches every exception, so the thread cannot die silently, and /healthz answers 503 if it has. A job found running at service start is charged as crashed (it may have killed the process), so a crashing job cannot loop the service. A clean shutdown (Worker.stop()) stops claiming and gives the job in flight back to the queue for free; its call is abandoned and its run is marked as service stopped.

The PWA shows each photo’s state under it (Capture from your phone (the PWA)): queued (“Waiting for Claude”, or “Waiting: Claude ingest is off”), processing, done, failed (with the reason and Retry) or paused (“Paused (reason): nothing is lost”, with Resume). A finished photo has a quiet Reprocess. There is no banner: the pause shows on every waiting photo, and GET /api/ingest and POST /api/ingest/resume are the queue’s status and the resume.

The Claude call#

claude.complete(model, system, messages, schema) returns the sanitised JSON, the raw content blocks, the usage and the served model.

  • The anthropic SDK, with ANTHROPIC_API_KEY from the service user’s env file (ingest.env, mode 600); no tools; SDK debug logging off (it logs request bodies).

  • Error text is stored and shown only after redaction: anything shaped like an API key (sk-ant-...), and the key itself, is removed, in case a server or proxy ever echoes the request headers.

  • max_retries=0 and a 240 s request timeout: the queue does all the retrying, so one claim is one call. The SDK’s own retries would triple a timeout and repeat a spend-cap 429 that cannot succeed.

  • SCRAP_VISION_MODEL, default claude-opus-5-5. Its thinking cannot be disabled, so effort is set explicitly (medium) and recorded. max_tokens is 16000. A board takes seconds to a minute or so; the 240 s timeout is the bound.

Image. Claude never gets the original, but a JPEG made from it by preview.for_claude: EXIF orientation applied, HEIC converted, quality 85. It is made one decode at a time and within a memory budget (400 MiB), so an image too large to decode is refused from its header and charged as class image. The result has the largest size with a long edge of at most 2048 px (2000 px on a Claude seat, below) and ⌈w/28⌉·⌈h/28⌉ ≤ 4784 image tokens (the high-resolution cap), never above the original: a 4:3 photo is sent as 2048×1536 and a square one as 1932×1932.

The image block sets "transformations": {"oversized_image": "error"}, so the API never rescales it silently and drawing coordinates are in sent pixels. The JPEG is stored as a blob (model_run.sent_sha256) with its image_width and image_height. The PWA scales the drawing to the displayed photo, and a later conversation can replay the exact bytes. scrap gc counts sent_sha256 as in use; after a purge it is an orphan that gc removes.

Output: kind (whiteboard, handwriting, diagram, screenshot, document, photo or other), title, tags, description, text (one item per line, (?) after uncertain readings) and elements (empty unless a whiteboard or diagram). The prompt lives in src/scrap/prompts/photo.md; prompt_version is <name>@<12 hex digits of sha256(prompt + schema)>.

Schema. It keeps to the documented structured-output subset (additionalProperties: false, no numeric or string bounds, limited unions), which [x, y] tuples would break. An element is one flat object: type, id, x and y are required, plus optional scalars or number lists, none a union: width, height, text, fontSize, label, labelFontSize, points (flat [dx0, dy0, dx1, dy1, ...]), start and end (shape ids), strokeColor and startArrowhead. Code makes Excalidraw skeletons of these and the sanitiser enforces bounds. id is required because, optional, the model leaves out every id and so every arrow.

On a Claude seat (SCRAP_LLM_BACKEND=cli)#

For a Team or Enterprise seat with no API key (ADR 0021). complete() hands the call to claude_cli.py, which runs claude -p once per call and returns the same Completion; everything after the call is shared. That is every Claude call: photos, and text enrichment (tags, summary, Ask Claude, the nightly related pass), whose text turn goes in the same way with the text model’s --effort and max_tokens (CLAUDE_CODE_MAX_OUTPUT_TOKENS). Nothing in scrap needs a tool: links are fetched by scrap.

  • Auth: CLAUDE_CODE_OAUTH_TOKEN from claude setup-token, in ingest.env. Without it, or without the claude binary, the worker pauses at start (auth) and logs why.

  • Input: one stream-json user message on stdin holding the image block (base64) and size text that scrap records; our prompt in place of Claude Code’s system prompt. The photo’s long edge is at most 2000 px, not 2048: the CLI rescales anything longer (and adds its own note on scaling coordinates). The CLI is not a pass-through: it re-encodes a JPEG over about 500 KB (same size in pixels), drops the block’s transformations, prefixes the system prompt, adds a message describing its environment, and may make a second request if the model does not call StructuredOutput (see ADR 0021).

  • Lock-down: --tools "", --permission-mode dontAsk, --strict-mcp-config with no servers, --setting-sources "", --disable-slash-commands, --no-session-persistence, --model, --effort and --json-schema on every call; a throwaway HOME and working directory; an environment of PATH, the token, proxy and CA settings only; CLI retries off, prompt caching off, 540 s for the process and its children (two request timeouts and start-up). A run whose init message offers any tool but StructuredOutput or any MCP server, or that has no init message, is discarded and pauses ingest (auth).

  • Output: the result’s structured_output; the stored content blocks are the StructuredOutput tool call, usage is the CLI’s with its total_cost_usd, which is the run’s cost_microusd and so counts towards the daily budget (a notional figure on a seat); for a model the CLI has no list price for (costBasis not list: Haiku and Sonnet 5.5 on 2.1.281), scrap’s PRICES cost the usage instead. A run killed at the deadline keeps the usage of the requests it got answers to.

  • Errors: the CLI’s error kind and status map onto the classes below. A run is failed if any request in it failed, even if the CLI went on to report a success (as it does after the API rejects the image: it drops the image and asks again without it). A seat’s usage limit (a rejected rate_limit_event) is an outage that waits for its reset (at most an hour at a time). Overage (isUsingOverage: past the limit, where calls may be billed) is a credit pause until Resume, so a person checks before more is spent; that run’s answer is not stored and the photo is sent again after Resume.

Stored context#

A model_run row is one call: the system prompt, messages and parameters in request (images as blob references, never base64), the content blocks exactly as returned in response (thinking blocks and signatures included), the sanitised output with its warnings, usage, cost_microusd, status and error_class. A run cannot be deleted while a version uses it. The schema is in 0002_ingest.sql.

A conversation (not built yet) would continue run R by sending R’s system prompt and messages, R’s response unchanged as the assistant turn, and a new user turn, on R’s model. model_run.parent_id is there for it. MCP does not expose runs: read lists each image with its URL and what Claude read from it, and Claude’s own additions (summary, tags, related pages) under by_model. See MCP server.

Derived results and versions#

Migration 0002 creates derived, which holds results as versions:

  • One current row (superseded_at IS NULL, a partial unique index) per (capture, photo, kind); inserting one supersedes the old (a trigger). Rows never change otherwise (more triggers); Restore inserts a copy.

  • Kinds. ocr, description (its data keeps the image kind) and excalidraw (data is {"format": "skeleton" | "scene", "width", "height", "elements"}). The table also allows summary and fetched; enrichment keeps those in enrichment instead.

  • Producer: the model id with its run_id, or human with author. A reprocess over a human drawing stores its drawing already superseded unless the user confirmed. The confirmation is kept on a job already queued or running (the worker reads it as it finishes), so it is never lost.

  • Restore copies the version’s producer, run, author and text; its data adds restored_from and restored_by, so the history can say so.

Page fields come from the first photo, and the user wins:

  • Title. The provisional title (first line of text, else the URL, else the device date) stays in rev 1 as captured. Only the first photo of a capture without text may replace it, once, on the page row only, adding no revision (ingest.TITLE_CAS: it applies only while the title still equals rev 1’s and there is no later revision). The same transaction re-indexes the page. PATCH /api/pages/{id} treats a title equal to the title at its base_rev as unchanged, so the PWA, which always sends the title it loaded, never undoes the model’s. The slug never changes (the PWA uses the id).

  • Tags join the page’s own on the first reading of its first photo, the user’s first: Claude’s fill what the user’s leave of the page’s 64. A later reading (Reprocess) adds them only to a page with none, so a tag the user took off stays off. Photo tags are cleaned to lower case, words joined by -, at most 64 characters each, at most 10 per reading.

  • Kind changes only while it is an unfixed note: whiteboard and diagram become whiteboard, document becomes document (ingest.PAGE_KINDS).

Search. A trigger indexes a current version’s text as a chunk of its page (with derived_id), and superseding removes it. That covers OCR, the description and a human drawing’s labels; a model drawing’s text is empty, because its words are the OCR. Store.index_page rewrites only the chunks with derived_id IS NULL, and search groups hits by page.

Excalidraw in the PWA#

A Vite dynamic import() loads @excalidraw/excalidraw and React only when a drawing is shown; the base app stays small. convertToExcalidrawElements expands skeletons in the browser with two workarounds: an arrow bound to free text carries that text’s x/y in start/end, and the scene is converted again after document.fonts.ready. The code is in web/src/board/.

  • On the page the drawing is a static SVG from Excalidraw’s exportToSvg, framed like the photo (its viewBox is the frame, so it lines up with the photo whatever the photo’s size), rendered when it nears the screen and kept in memory. It behaves like an image: no gestures, so a finger drag scrolls the page. Its aspect ratio comes with the page (ingest.drawing has the frame), so nothing shifts when it renders. Wide screens show it beside the photo; narrow ones (a phone held upright) show one at a time, with a Photo / Drawing switch.

  • Tapping it opens the full-screen viewer: a layer sized to the visual viewport with a history entry (Back closes it), Excalidraw in view mode fitted to the frame, and Edit switching the same scene to edit mode, so zoom, scroll and edits survive the switch. Edits are kept as a draft in IndexedDB as they change. Photo shows the photo beside the drawing (landscape) or over it (portrait). Save (in edit mode) stores the scene with its base version (409 if stale) as a human version whose labels become text; History has Restore; the viewer exports to .excalidraw, PNG and SVG; the image tool is hidden.

  • Fonts. Excalidraw’s drawing fonts, but not Xiaolai (CJK, 14 MB), are copied from the package into the build (/excalidraw/fonts/) and fetched only when used. Excalidraw always lists its CDN as a fallback source; the app’s CSP, font-src 'self' data:; connect-src 'self', keeps it from ever using it (Chrome logs each blocked fallback). The preview skips Excalidraw’s font inlining (the page already has the fonts); exported SVGs inline them.

  • The second workaround is done before anything is shown: convert, export the text to a 1 px canvas (which makes Excalidraw load the fonts it uses), wait for document.fonts.ready, convert again.

  • Sizes. npm run size checks them in CI. The app shell’s JavaScript is budgeted at 16 kB gzipped (about 15 kB now, plus about 8 kB of CSS); the viewer chunk loaded on demand is about 400 kB of JavaScript and 23 kB of CSS gzipped, and the fonts about 350 kB. scrap gzips its scripts, styles, pages and JSON for clients that accept it (not files, previews, downloads, fonts or range requests), so gzipped sizes are what crosses the network.

  • Offline. The service worker precaches the shell and a short list of screen chunks (OFFLINE in web/vite.config.ts: composer, editor, page edit, render, sharing, refine and searches), never the drawing viewer or its fonts. The viewer and fonts are fetched when a drawing is first opened.

  • Reprocess shows Replace mine / Keep mine when the current drawing is a human one, and {queued, already} in the reply says whether the photo was waiting already.

  • Downloads. The page’s zip carries <photo>.excalidraw beside each photo; a model skeleton is converted on the server, approximately (Excalidraw re-measures text when it opens it). The viewer’s own exports are made by Excalidraw in the browser.

Spend and outage control#

A price table (claude.PRICES, dollars per million tokens) turns each run’s usage into cost_microusd: claude-opus-5-5 is $4 in / $20 out, claude-sonnet-5-5 $2 / $10 and claude-haiku-5-5 $0.10 / $0.50 (for prompts up to 100k tokens, which enrich’s never reach), with cache write and read rates too. A model that is not in the table is priced at the DEAREST fallback, $10 in / $50 out, so an unlisted model’s cost is over-estimated rather than under-estimated; add the model to PRICES to get its real price.

The budget is SCRAP_BUDGET_DAY_USD (default 3), for photos and text pages together: the sum of cost_microusd of the runs started since UTC midnight, in model_run and enrich_run. It is checked when a job is claimed, not during a call, so the call that crosses the line still finishes and the day can end a little over; the Console spend limit is the hard cap. Once it is reached, the job is given back and the queue pauses (reason budget) until UTC midnight, or Resume. Resume does not raise the budget: the next claim sees the spend still over and pauses again, so raise SCRAP_BUDGET_DAY_USD and restart if you want to go on today.

The rule. A pause refunds the claim: the job stays queued with run_after set to the failure’s time, behind older jobs, while the pause gate waits. Resume, or the pause running out, makes it claimable again, so an outage fails nothing. Every charged failure adds 1 to job.failures and retries 10 minutes later (invalid output at once); the third kills the job (dead, shown as failed with Retry). The SDK’s APITimeoutError subclasses APIConnectionError, so it is tested first, else every timeout would be a free outage retry. A success clears the pause.

Notification. The first pause of an episode (or a pause for a new reason, such as a spend limit after a budget pause) POSTs once to SCRAP_NOTIFY_URL (off when unset; an ntfy topic works) with the fixed text scrap: Claude ingest paused ({reason}). Open scrap to resume. It names only the reason, never titles, OCR or API errors.

What is sent to Anthropic#

Only when ingest is on and only to the Claude API:

  • A photo: the JPEG described above (a resized, re-encoded copy; only its colour profile is kept from the original’s metadata) and the fixed prompt. Nothing else about the page is sent.

  • A note, todo or read: its kind, tags, title and text as plain words (at most 12,000 characters), a list of the tags already in use with their counts (at most 600 tags), and the fixed prompt.

  • A saved link: the same, plus the link’s readable text (at most 20,000 characters) fetched by scrap. The fetched text is sent, not stored.

  • Related pages: the page in brief and an index of up to 150 candidate pages, each a title, up to 6 tags and a summary cut to 150 characters.

Nothing is sent for a page in the trash. Apart from Claude, the only outbound requests are the link fetches above (to the linked site) and SCRAP_NOTIFY_URL, which gets a fixed line with the pause reason. Everything sent is kept in the database in model_run and enrich_run (photos as references to the stored JPEG), so it is covered by the same backups as the pages.

Enrich: text pages and links#

Photos get tags from their own reading; notes, todos, reads and saved links get them from a second job kind, enrich (src/scrap/enrich.py), on the same worker thread, queue pause and daily budget (20. Text enrichment: Claude tags, summarises and relates text pages, apart from the text). One tool-less call per page, structured output, schema-checked: Claude adds tags and a summary, and for a link a title. Related pages are a call of their own. Nothing edits the page’s text. The schema is in 0009_enrich.sql.

  • Model. SCRAP_TEXT_MODEL, default claude-haiku-5-5; SCRAP_TEXT_EFFORT, default low; max_tokens 4000. SCRAP_ENRICH=off turns it off while photo ingest stays on.

  • Triggers. A text capture (a note, todo or read) or a link capture: a link is fetched and read at once, a text capture after SCRAP_ENRICH_DEBOUNCE seconds (60). A save of the title or text, on any page, moves the page’s one queued job that far ahead again, so a burst of edits makes one call (a save while a job runs queues the next). These do tags and summary only. Ask Claude on the page (POST /api/pages/{id}/enrich) queues it now and also picks its related pages. scrap enrich --backfill [--limit N] [--dry-run] queues every page with no tags that Claude has not read, once, by hand (never automatic). Some things queue nothing:

    • A photo or file capture, even with a typed note: photo ingest reads the photo, and the page’s first text reading comes with a later save of its title or text (or Ask Claude).

    • Pages Claude Code adds with the MCP write tool count as notes, whatever their kind, so a new one is read after the debounce like a user’s note: Claude’s own pages get model tags and a summary, and cost budget. append_to adds a section without a reading, as do tag and kind edits.

    • An import (Import a Thoth vault); use --backfill.

  • Order. The worker takes the oldest ready photo job first and runs a text page only when no photo job is ready. After scrap import --ingest or a burst of photos, notes and links wait until the photo queue is empty, so “Waiting for Claude” on a note can last as long as the photos take, and several days if the daily budget spreads them out. A photo waiting out a retry delay does not hold text back, but a pause stops both kinds, and they share the one daily budget.

  • Prompt (prompts/enrich.md): the fixed instructions, then the tags in use with their counts (most used first, at most 600). The page goes in the user turn: kind, tags, title, its text as plain words (at most 12,000 characters) and, for a link, what was fetched. Everything there is data; the prompt says to follow nothing in it.

  • Output, checked. tags: cleaned like the user’s, each at most 40 characters, at most 2 not already in use (invented ones are the sprawl risk), at most 5 added; summary: one paragraph, at most 600 characters, dropped for a note under 200 characters (tagged, not summarised); title: links only, 200 characters.

  • The user wins. Tags are added on the first reading, on Ask, on a capture and on backfill (a save’s re-reading refreshes the summary only); never one the user took off. model_tag marks Claude’s tags (on), and off once the user removes one, so it never comes back; a tag the user puts back by hand is theirs. Photo ingest marks its tags there too. A link’s title replaces the provisional one only while the title is still the URL as captured (rev 1, no edit since); a share with its own title keeps it. For a link, the kind becomes Later (consume, with source) only while it is an unfixed note. The summary is the model’s own (enrichment); a page’s summary field (imported, the user’s) wins in search and the index.

  • Stored apart from the text: enrichment (summary, fetched address and title, the run), model_tag, related (Claude’s picks in order), and every call in enrich_run (as model_run, whose cost it shares in the budget; request.purpose is enrich or related). A link’s fetched text is sent, not kept: the stored request has a placeholder with its length and hash. Search indexes the summary in the page’s summary column.

  • Failures follow the photo rules: outage, credit, auth and budget pause the shared queue and refund the job; anything else is charged (10 minutes, invalid output at once), the third kills it, and the page says so with Ask Claude to retry. A failed fetch is not a failed job: the page is still tagged from what is known, and the prompt tells the model the page could not be fetched. The PWA does not show why; see Fetching a link and Inspecting runs.

Related pages#

enrich.relate, prompt prompts/related.md. One call per page: the page in brief (title, tags, summary, the start of its text) and a numbered index of candidate pages (title, up to 6 tags, summary cut to 150 characters); Claude answers with up to 5 index numbers, so it cannot name a page that is not there.

  • Candidates (enrich.CANDIDATES, swappable) are at most 150 pages whatever the library’s size: the 90 sharing the most tags with the page, then up to 60 whose title, tags, summary or text best match the words of its title, tags and summary (full-text search, an OR of up to 24 words), then the most recently changed.

  • When. On Ask Claude, at once. Otherwise scrap enrich --related [--all] [--limit N] [--dry-run], the nightly pass, does every page changed since its last picks (no related run newer than its updated_at; --all: every page). It runs in the command’s process (in the container: podman exec scrap scrap enrich --related), checks the shared queue pause and the day’s budget before each call, and stops at either (an outage, credit or auth error pauses the queue as the worker does); other failures are counted and it goes on. Exit status 1 when stopped. On a single server, deploy/scrap-enrich-related.{service,timer} run it nightly (03:41) in the service’s container, and install.sh enables the timer if the image has the command. While ingest or enrich is off, or no key (or, with SCRAP_LLM_BACKEND=cli, no seat token) is set, the command prints a note and exits 0. The Helm chart has no equivalent yet (see Enabling ingest).

  • Both ways. A page’s Related merges its picks, pages that picked it, and pages linking here with [[slug]] (marked “links here”), each once, at most 8. So a new page that picks an older one shows on the older one too, without a call for the older page.

  • MCP read returns all of this under by_model (summary, Claude’s tags, related), labelled as written by a model, not the user.

Fetching a link#

src/scrap/fetch.py. The page is untrusted:

  • http(s) only, standard ports, no login in the address, no proxy, no cookies;

  • every address the name resolves to must be global (no private, loopback, link-local and metadata 169.254.169.254, CGNAT/tailnet 100.64/10, ULA, multicast or reserved, nor IPv4-compatible ::/96, NAT64 64:ff9b::/96 or site-local fec0::/10; IPv4-mapped IPv6 judged as IPv4), checked again at each of at most 5 redirects, and the socket connects to the checked address (TLS still verifies the name), so a second DNS answer cannot swap it;

  • at most 2 MB after decompression (a gzip bomb stops there), 20 s for the whole fetch (the socket is cut at the deadline wherever it waits, so a site sending a byte at a time cannot hold the worker); a body that does not decompress is refused;

  • a path or query that is not ASCII is sent percent-encoded (%XX already there kept), an international name as IDNA;

  • HTML, XHTML or plain text only; the readable text is the <article> (else <main>, else <body>) without scripts, styles, menus, headers, footers and forms, at most 20,000 characters, with the page’s title and description.

The request. A plain GET with these headers: User-Agent: scrap/1 (personal notes; fetches a page its owner saved) (fetch.AGENT; match it in a site’s logs or an egress allow-list), Accept: text/html,application/xhtml+xml,text/plain;q=0.8, Accept-Encoding: gzip, deflate and Accept-Language: en. scrap does not read robots.txt: it fetches one page, once per reading, because its owner saved the link. A reading fetches the link again, whether from Ask Claude, a save or a retry.

When it fails. The reason is not shown in the PWA. The job still succeeds: the page is tagged from the link and the text the user typed, with no title or summary taken from the site, and the reason is kept only in the run’s request under fetch (read it as in Inspecting runs; a page that was fetched has {"url", "chars"} there instead). Inspecting runs#

There is no screen or MCP tool for runs (read shows only their results), so an operator reads them from the status route, the logs and the database.

Quick checks. GET /api/ingest returns whether ingest is enabled, whether the queue is paused (with reason and paused_until), jobs (photo jobs by state), enrich (whether it is on, and its jobs by state) and spent_today_usd. On a single server, call it on the socket, as the deploy page does for /healthz:

curl --unix-socket "$XDG_RUNTIME_DIR/scrap/scrap.sock" http://localhost/api/ingest

(on Kubernetes, kubectl -n scrap port-forward svc/scrap 8000:80 and the same path on http://127.0.0.1:8000). The logs are journalctl --user -u scrap, podman logs scrap or kubectl -n scrap logs deploy/scrap. The worker logs a traceback only for an unexpected exception, under ingest worker, ingest job N or enrich job N; API errors, pauses and fetch failures are not logged (apart from a failed pause notification); they are in the database.

Detail. Read scrap.db with Python’s sqlite3, because the image has no sqlite3 command. Open it read-only, inside the container where the data is at /data:

podman exec scrap python -c '
import sqlite3
c = sqlite3.connect("file:/data/scrap.db?mode=ro", uri=True)
for row in c.execute("SELECT ..."):
    print(row)'

(on Kubernetes, kubectl -n scrap exec deploy/scrap -- python -c '...'). The SELECTs below were run against a database made by scrap’s own code.

Cost per day, photos and text together (the budget’s own sum):

SELECT day, round(sum(usd), 4) FROM (
  SELECT substr(started_at, 1, 10) AS day, cost_microusd / 1e6 AS usd FROM model_run
  UNION ALL
  SELECT substr(started_at, 1, 10), cost_microusd / 1e6 FROM enrich_run)
GROUP BY day ORDER BY day DESC LIMIT 14;

The latest runs that did not succeed, with the class from the table above and the (redacted) error:

SELECT * FROM (
  SELECT 'photo' AS what, started_at, status, error_class, error
    FROM model_run WHERE status <> 'ok'
  UNION ALL
  SELECT 'text', started_at, status, error_class, error
    FROM enrich_run WHERE status <> 'ok')
ORDER BY started_at DESC LIMIT 10;

Why a link got no summary or title, newest first (a NULL is a note, which has no fetch):

SELECT p.title, json_extract(r.request, '$.fetch')
FROM enrich_run r JOIN page p ON p.id = r.page_id
WHERE json_extract(r.request, '$.purpose') = 'enrich'
  AND json_extract(r.request, '$.fetch') IS NOT NULL
ORDER BY r.started_at DESC LIMIT 10;

The fetch value is a reason from the fetch table, or {"url": ..., "chars": N} when the page was read. The queue state is in job and enrich_job (state, failures, last_error, run_after). A run with status running is a call in flight.

Two cautions. cost_microusd is an estimate from the run’s usage and claude.PRICES (see Spend and outage control), so the Console is the authority on what you spent. And the runs hold your content: model_run keeps the JPEG that was sent (sent_sha256, a blob) and enrich_run keeps the system prompt and the page text (a fetched page’s text is a placeholder), so the database holds what you sent to Claude, and your backups do too.

Command line#

Command

Use

scrap ingest-once IMAGE [--save FILE]

Try one image against Claude with no database; numbers only unless --save

scrap enrich --backfill

Queue the pages with no tags that Claude has not read; the service’s worker runs them

scrap enrich --related [--all]

Pick related pages now, in the command’s process (the nightly pass)

scrap import DIR --ingest

Import a vault and also queue its images for Claude; see Import a Thoth vault

The full option lists are in HTTP API and CLI. A large import with --ingest queues one job per image, so the daily budget decides how many days it takes; the queue works through them and pauses at the budget each day.

Troubleshooting#

Symptom

Cause

Fix

Photos say “Waiting: Claude ingest is off”

SCRAP_INGEST is not on

Set it (see Enabling ingest) and restart

Paused (auth)

The key is wrong or revoked (401, 403), or the model name is unknown (404)

Fix ANTHROPIC_API_KEY or SCRAP_VISION_MODEL, restart, then Resume

Paused (credit)

Out of credit, or at the Console spend limit

Add credit or raise the limit, then Resume

Paused (budget)

The day’s spend reached SCRAP_BUDGET_DAY_USD

Wait for UTC midnight, or raise the budget and restart; Resume alone pauses again

Paused (outage)

The API is unreachable, failing or rate limiting

Nothing: it backs off and retries; Resume tries at once

A photo says Failed

Three charged failures (see the table above); the reason is shown

Retry; for an image failure the photo may be too large to decode

A drawing is missing

The photo was not a whiteboard or diagram, or the model returned none (warnings are in the run’s output)

Reprocess

/healthz returns 503

The ingest thread has died

Read the logs and restart

A note or link is never tagged

SCRAP_ENRICH=off, ingest off, the page is still inside the debounce, or photo jobs are queued ahead of it (text runs only when no photo job is ready)

Check the settings and GET /api/ingest; Ask Claude queues it now, but still behind ready photos

A saved link has no summary or a poor title

The page could not be fetched or the site blocked scrap, so Claude had only the address and the user’s text; the PWA does not show this

Read the reason (Inspecting runs, and the table in Fetching a link); Ask Claude fetches the link again

scrap enrich --related prints a note and does nothing

Ingest or enrich is off, or ANTHROPIC_API_KEY is not in the command’s environment

Run it in the container (podman exec scrap ...)

Risks#

Thinking: with structured output at effort medium the model may not think on a board (raise the effort if drawings fall short); Excalidraw API drift (the version is pinned); model drift (prompt_version traces it).
