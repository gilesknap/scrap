Connect a Claude Code session#

Claude Code sessions can search, read and write scrap through its MCP server (see MCP server). Nothing is installed on the session’s machine: it talks to /mcp.

How the session reaches /mcp depends on where scrap runs:

        flowchart LR
    CC["Claude Code"] -->|"http://localhost:8000"| L["scrap, same machine"]
    CC -->|"HTTPS, tailnet"| T["Tailscale Serve / operator"]
    CC -->|"HTTP, home network"| N["scrap on LAN"]
    CC -->|"bearer + service token"| CF["Cloudflare Access"]
    L --> M["/mcp"]
    T --> M
    N --> M
    CF --> M
    classDef claude fill:#fff3e0,stroke:#e08a00
    classDef store fill:#e8f1ff,stroke:#4a7bd0
    class CC claude
    class L,T,N,CF,M store

  • Tailnet: HTTPS (Install on a server with Tailscale). Home network: plain HTTP (Try scrap on your LAN). Kubernetes: Cloudflare Access with a bearer token (see “If /mcp needs a token” below, Install scrap on Kubernetes and ADR 0023).

  • Claude Code in claude-sandbox: follow Connect Claude Code in claude-sandbox instead; it reaches scrap on a port of the host.

  • On your own machine, run scrap as in “Try it” in the README and add http://localhost:8000/mcp in step 2; step 1 is not needed on loopback.

Before you start you need:

  • scrap running and reachable from the machine running Claude Code: on the same machine or LAN (Try scrap on your LAN), published on your tailnet (see Install on a server with Tailscale, Deploy on a single server, “Publish on your tailnet”, or Tailscale Kubernetes operator (recommended)), or on Kubernetes behind Cloudflare Access (Install scrap on Kubernetes);

  • the Claude Code CLI on that machine;

  • optionally, ingest on (SCRAP_INGEST=on) if you want Claude to describe photos (see step 2).

1. Tell scrap its address#

/mcp answers only requests addressed to loopback or to SCRAP_PUBLIC_URL. Put the address that Tailscale Serve gives scrap (the --https port you chose when you published it; 8446 is only an example) in ~/.config/scrap/ingest.env, scrap’s own settings file (keep it mode 600; install.sh creates it so), for example:

SCRAP_PUBLIC_URL=https://myhost.my-tailnet.ts.net:8446

then systemctl --user restart scrap. Run both as the dedicated scrap user, in a real login session (ssh scrap@<host>, or sudo machinectl shell scrap@; see Deploy on a single server).

The address must be a full URL with the scheme, and must match what clients use, port included: a request whose Host differs gets 421 Invalid Host header. You can give several addresses, comma separated; the first makes the page links the tools return. Without it, those links are bare /p/<slug> paths that cannot be clicked.

On Kubernetes the chart has no setting of its own for it: pass it with extraEnv, using the Tailscale operator’s address (no port, since it serves on 443):

extraEnv:
  - name: SCRAP_PUBLIC_URL
    value: https://scrap.<tailnet>.ts.net

2. Add the server to Claude Code#

On a machine on the tailnet:

claude mcp add --transport http --scope user scrap https://myhost.my-tailnet.ts.net:8446/mcp

The default scope is local (this project, only you); --scope user makes it available in all your projects. Avoid --scope project: it writes the tailnet hostname into a .mcp.json that you would commit. claude mcp list should show scrap as connected. claude mcp remove scrap takes it out again.

The server has fifteen tools (eleven with SCRAP_MCP_CONTENT_EDIT=0, which drops edit_page, edit_drawing, trash_pages and undelete), which appear as mcp__scrap__search (it also lists the recent pages and the todos), mcp__scrap__read, mcp__scrap__drawing, mcp__scrap__tags, mcp__scrap__topics, mcp__scrap__write, mcp__scrap__edit_meta, mcp__scrap__rename_tag, mcp__scrap__revisions, mcp__scrap__revert, mcp__scrap__edit_page, mcp__scrap__edit_drawing, mcp__scrap__trash, mcp__scrap__trash_pages and mcp__scrap__undelete; the Tools table in MCP server says what each takes and returns.

Try it: ask “get my recent photos”. Search results say which pages hold images (image_count, and the first image’s kind, description and thumbnail URL), and has:image or image:photo lists them newest first; see MCP server. The kind and description are there only once ingest has read the photo (SCRAP_INGEST=on), and the image URLs can be fetched only from the tailnet (see “Images” in the reference).

Check it from a shell without Claude:

curl -si https://myhost.my-tailnet.ts.net:8446/mcp \
  -H 'Accept: application/json, text/event-stream' -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

It should print an HTTP 200 status and JSON with fifteen tools in result.tools.

Off the tailnet, or for a quick test, use the SSH tunnel fallback (Fallback: an SSH tunnel) and add http://127.0.0.1:8790/mcp instead; loopback needs no SCRAP_PUBLIC_URL. A session that cannot reach the tailnet (a hosted or cloud Claude session, claude.ai) cannot use scrap this way, unless scrap is published through Cloudflare Access with a service token and a bearer token (below).

If /mcp needs a token#

If scrap has SCRAP_MCP_TOKEN or SCRAP_MCP_TOKEN_FILE set (see MCP server), send the token as a header. With claude mcp add:

claude mcp add --transport http scrap https://myhost.my-tailnet.ts.net:8446/mcp \
  --header 'Authorization: Bearer ${SCRAP_MCP_TOKEN}'

or in .mcp.json, where Claude Code expands ${VAR} in header values, so the token can stay in the environment (or an env file you do not commit):

{
  "mcpServers": {
    "scrap": {
      "type": "http",
      "url": "https://scrap.example.com/mcp",
      "headers": {"Authorization": "Bearer ${SCRAP_MCP_TOKEN}"}
    }
  }
}

Behind Cloudflare Access, add its service-token headers too, so the request carries CF-Access-Client-Id: ${CF_ACCESS_CLIENT_ID}, CF-Access-Client-Secret: ${CF_ACCESS_CLIENT_SECRET} and the Authorization header. Keep all of these in an env file and do not commit it.

If it does not connect#

  • 401: scrap wants a bearer token and the client sent none, or a wrong one. Check the header above; a curl check needs -H "Authorization: Bearer $TOKEN" too.

  • 421 Invalid Host header: the Host the client used is not loopback or in SCRAP_PUBLIC_URL (unset, wrong, or a different port). Fix step 1 and restart scrap.

  • 403: the request carried an Origin that is not one of those addresses.

  • claude mcp list shows scrap as failed: the machine is off the tailnet, nothing is published at that address, or the tailnet ACL blocks the port. Check the address itself with ./deploy/smoke.sh <url>; see Troubleshooting and the Tailnet ACL section of Deploy on a single server.

  • It worked and stopped after the address changed (a new SCRAP_PUBLIC_URL, another Tailscale Serve port, or a move to the Kubernetes ingress): scrap reads SCRAP_PUBLIC_URL only at startup, so restart it (systemctl --user restart scrap; on Kubernetes, helm upgrade rolls the pod) for the new address to be accepted. Claude Code keeps the URL you registered and does not rewrite it, so register the new one: claude mcp remove scrap, then the claude mcp add of step 2 with the new <url>/mcp (and the same --scope). A restart of scrap alone needs nothing in the session: /mcp keeps no session state, so the next call just works.

  • 413: a request over 2 MiB.

  • A tool error such as “only a page written over MCP can be appended to”, or a title over 200 characters, a body over 200 kB or more than 20 tags: the call is refused and nothing is saved.

3. Install the sc commands and the scrap-links skill#

commands/ in this repository holds Claude Code slash commands that give you short scrap commands. Each is one Markdown file with a one-line description, and each is its own command, so typing /sc in Claude Code autocompletes the whole set with that description. They use the server added in step 2 (the mcp__scrap__* tools) and do nothing useful without it; if the tools are missing they say so and print the claude mcp add line.

Command

What it does

/sc-post [title]

Posts Claude’s previous response to scrap verbatim, as one page. “post this to scrap” works too.

/sc-summarise [all] [title]

Summarises the current topic (the latest activity) into one page and posts it (below). With all, the whole conversation: overview, timeline, findings, decisions, changes made and open questions.

/sc-find <words>

Searches scrap and shows the top results as short lines.

/sc-todos

What to do now, overdue first.

/sc-tidy <what>

Bulk kind and tag changes with edit_meta: a dry_run first, a before and after for you to approve, then the change and its batch id.

/sc-undo

Lists recent revisions and reverts the one you name.

/sc-write <what>

Writes one new page from your instructions, picking out only what you ask for from the conversation (“the URLs we discussed and why”). Uses only the conversation, lists anything uncertain under Unsure, and reuses existing tags. Always creates a page.

/sc-answer <question>

Answers from scrap alone: searches, reads the pages, and cites them as links; says “not in scrap” rather than using general knowledge. Read-only.

/sc-edit <page> <change>

Changes the text of an existing page with edit_page: a dry_run diff first, then the edit once you agree. /sc-undo reverts it.

/sc-done <todo>

Ticks off a todo’s task boxes with edit_page (the todo becomes done when all are ticked). A todo with no task boxes cannot be closed over MCP: mark it in the app.

/sc-recent [period]

What changed lately (default 1d), by you and by Claude, from the revisions feed and search. Read-only.

/sc <words>

An index: searches like /sc-find, or lists the commands above.

Install them for all your projects with one command:

curl -fsSL https://raw.githubusercontent.com/gilesknap/scrap/main/commands/install.sh | sh

It copies the files into ~/.claude/commands (set CLAUDE_COMMANDS_DIR to put them elsewhere, such as .claude/commands for one project). From a clone of this repository you can instead copy commands/*.md yourself, or symlink them to keep up to date with the repository: ln -sfn "$PWD"/commands/*.md ~/.claude/commands/. Start a new Claude Code session afterwards, and type /sc to check that the commands are listed. Copy the files unchanged.

The same command installs the scrap-links skill (skills/scrap-links in this repository). It makes every scrap item an answer surfaces a clickable link, in any question you ask about scrap, not only in the sc commands: a todo, note or search result is shown as [Title](url), never as a bare slug or plain title. It goes into ~/.claude/skills/scrap-links (set CLAUDE_SKILLS_DIR to put it elsewhere, such as .claude/skills for one project). From a clone you can copy the folder yourself, or symlink it: ln -sfn "$PWD"/skills/scrap-links ~/.claude/skills/. To check it is loaded, start a new Claude Code session: scrap-links is listed when you ask “what skills do you have”, and asking “what todos are for today” lists every todo as a link.

These commands replace the earlier single /s <verb> skill (/s post, /s tidy, and so on), the s- and sc- skill sets that briefly preceded them, and the older scrap-post skill. Delete ~/.claude/skills/s, ~/.claude/skills/s-*, ~/.claude/skills/sc and ~/.claude/skills/sc-* (a skill and a command of the same name clash) and ~/.claude/skills/scrap-post after installing these. Only the scrap tools are used. <SCRAP_URL> in the commands is a placeholder (the hint they give when the tools are missing, and the shape of the page URL they report); the real URL comes from the write tool, built from SCRAP_PUBLIC_URL.

/sc-summarise makes Claude summarise the useful findings of the current topic into one page (/sc-summarise all for the whole conversation), reusing existing tags and linking related pages, and show you the title and tags before it writes; say “just post” to skip the question.

The summary has a fixed layout: a one-line summary, then Findings, Decisions, Details and Open questions. It is a note unless it is a task (todo) or a longer reference (doc), carries the repository and date as its origin, and is sent with a random key so that a retry does not post twice. The command tells Claude to leave out secrets, credentials and private data. It appends to an earlier page only if that page was written by Claude (written_by_claude in read); otherwise it links to your page.

Pages written this way carry a Written by Claude badge and the origin the session gave; is:claude lists them. Claude never deletes a page for good: it can move pages you name to the trash (trash_pages, undone with undelete), and the nightly gc purges them after SCRAP_TRASH_DAYS days. It can change any page’s kind and tags (“make these 15 notes whiteboards”, with edit_meta); each such change is a revision you can ask it to list (revisions) and undo (revert). It can also edit the text of a page you name (“fix the typo in my trip notes”, with edit_page): it replaces one passage it quotes exactly, shows you a diff first if you ask, and refuses if the page changed since it read it. It can save a refined drawing too (edit_drawing, a new version in the drawing’s history). Each text edit is a revision too, which revert (with to_rev) undoes, and is:claude-edited finds the pages whose text it changed. A bulk change given as a search is refused if it finds more than 50 pages unless limit is raised (up to 200; naming the pages takes up to 200 as well), and Claude is told to try dry_run first. See “Kinds and tags” in MCP server.

Work on a phone page from Claude Code#

The Claude Android app cannot use scrap’s MCP server, so a page you are looking at on your phone reaches Claude Code through the clipboard:

  1. On the phone, copy the page’s URL (or share it to a note or message you can reach from your computer).

  2. In a Claude Code session with the sc commands, paste it: /sc <url>. Claude finds the page from the slug in the URL and reads it, with the image’s description and transcribed text.

  3. Ask about the drawing, or ask for a change. Claude gets the drawing with drawing and can answer questions, redraw it elsewhere (Mermaid, say) or save a refined version with edit_drawing.

A drawing saved this way is a new version, “drawn by claude”, in the drawing’s History in the PWA; nothing is overwritten, and if you edited the drawing in the meantime Claude’s save is refused. You can restore any earlier version there.

To have a session summary posted automatically before each compaction, install the PreCompact hook described in Post a summary to scrap when Claude Code compacts.

Permissions and security#

Claude Code asks before using an MCP tool unless you allow it, and the sc commands allow none. You might allow the read tools (mcp__scrap__search, read, tags) and let write, edit_meta and the rest keep asking.

To keep Claude off the text of your pages, set SCRAP_MCP_CONTENT_EDIT=0 on the server (edit_page, edit_drawing, trash_pages and undelete are then not offered, and revert refuses to_rev), or deny edit_page in one client’s settings: "permissions": {"deny": ["mcp__scrap__edit_page"]}. A client setting cannot deny only the text mode of revert, which also undoes kinds and tags.

scrap has no login: any device on the tailnet that can reach the port can use /mcp, so restrict that with the tailnet ACL (see Deploy on a single server). Off the tailnet, /mcp can require a bearer token (SCRAP_MCP_TOKEN, ADR 0023), behind Cloudflare Access on Kubernetes.

Mount scrap only in sessions where reading untrusted text is acceptable: pages may hold injected instructions, and a session that runs with bypassed permissions could be steered by them.
