# HTTP API and CLI

Milestone 1: quick capture end to end, with no LLM. Requests and responses are JSON unless noted.
Responses of text (JSON, the PWA's scripts, styles and pages) over 1 kB are gzipped for a client
that sends `Accept-Encoding: gzip`; stored files, previews, downloads, fonts and range requests
never are.
The service binds `127.0.0.1` and has no login; put Tailscale Serve (or an authenticating proxy)
in front. The author of a capture or edit is the `Tailscale-User-Login` header, else `tagged`.

## HTTP

| Method and path | Does |
| --- | --- |
| `GET /healthz` | Liveness: `{"status": "ok", "version": ..., "max_upload_bytes": ...}`; the PWA checks a capture's size against the limit before saving it. `503` (`"status": "ingest worker stopped"`) if ingest is on and its thread has died |
| `POST /api/captures` | Save a capture as a new page. JSON `{id, text?, url?, kind?, source?, created_at?, due?, priority?, tags?}`, or `multipart/form-data` with the same fields (a `tags` field per tag) plus one or more `file` parts. `id` is a ULID minted by the client: `201` the first time, `200` with the same reply on a retry. `kind` (`note`, `todo`, `consume`, `whiteboard` or `document`) is the user's choice: it fixes the page kind (`kind_fixed`, so ingest keeps it) and fills its default `fields`; without it the page is an unfixed `note`. `hint` (`todo` or `consume`) is the older name for `kind`, still accepted. `source` is `pwa` (the default) or `share`; `mcp` is refused here: only the MCP server writes it, so it marks a page Claude wrote. `due` and `priority` are a todo's only (as for `PATCH`; `422` with another kind). `tags` (a list of strings) are the new page's tags, cleaned as `PATCH` cleans them (`422` for a bad one, and nothing is saved), indexed at once; Claude adds tags to a photo's page only if it has none, so the user's win. A bare URL sent as `text` is treated as `url`. Returns `{capture_id, page_id, slug}`. `413` over the upload limit. Files are stored as sent (HEIC too) |
| `GET /api/pages?limit=50&kind=` | Pages, most recently changed first (by their text: a kind or `fields` change doesn't count); the trash is left out. `kind=todo` lists only that kind (any kind in the schema, `memory` and `reference` too; another is `422`; empty means all). Each has `kind`, `kind_fixed`, `fields`, and a todo's `due` and `priority` (`null` on other kinds); `thumb` is the SHA-256 of the page's first image, or `null` |
| `GET /api/pages/{id or slug}` | A page with `rev` (its current revision), `tags` (most used first), `removed` (the SHA-256s of files an earlier revision's text referred to and the current text does not: the PWA no longer lists them), and its captures and their files. Each file of a photo has `ingest`: `null` if it was never queued, else `{state, failures, error, text, description, image_kind, drawing}` (`drawing`: `null`, or the current version's `{id, version, producer, width, height}`), `state` being `queued`, `processing`, `done`, `failed` or `paused` (see [](../explanations/ingest.md)) |
| `PATCH /api/pages/{id or slug}` | `{base_rev?, title?, body?, kind?, fields?, tags?, due?, priority?}`. A `title` or `body` writes a new revision and needs `base_rev`: `409` with the current `rev` if it is stale (and nothing in the request is saved). A `title` equal to the title at `base_rev` counts as unchanged, so it never undoes a title Claude set meanwhile. `kind` (as for a capture) sets `kind_fixed` (ingest then never changes it); a different kind keeps every field the page has and adds that kind's defaults for keys it lacks: `todo` `{"status": "open"}`, `consume` `{"subtype": "read", "status": "open", "source"}` (`source`: the capture's URL, if any). So nothing is lost by changing a kind and back; a `status` already there keeps its value. `fields` changes them, e.g. `{"status": "done"}` ticks a todo; a `null` value removes one; names are 1 to 40 characters, values flat (a string of at most 200 characters, a number or a boolean), and a page has at most 32 fields (`422` otherwise). `tags` replaces all the page's tags (`[]` removes them), each cleaned as an import's are (one space between words, no leading `#`, lower case, 1 to 64 characters, each once; at most 64 tags, `422` otherwise). `due` (a date, `YYYY-MM-DD`: no time, no time zone) and `priority` (`high`, `medium` or `low`) are a todo's own columns, not fields: sent, they set it, `null` clears it, not sent keeps it; a value is `422` on a page of another kind (after any `kind` in the same request: `{"kind": "todo", "due": ...}` works), as is a malformed one. A page that stops being a todo keeps them (a stray tap loses nothing), but they are ignored, and returned as `null`, until it is one again. Neither `kind`, `fields`, `tags`, `due` nor `priority` is a revision, nor changes `updated_at`. Returns the page |
| `POST /api/captures/{id}/reprocess` | `{photo?, replace_human?}`: send a photo capture's images (or the one with SHA-256 `photo`) to Claude again; also the *Retry* of a failed one. A new drawing replaces one the user drew only with `replace_human: true` (otherwise it is kept in the drawing's history only); the confirmation also reaches a photo already queued or running. Returns `{queued, already}`: how many were added, and how many were queued or running already |
| `GET /api/captures/{id}/photos/{sha256}/drawing` | The photo's current drawing: `{id, version, producer, author, run_id, created_at, current, format, restored_from, data}`. `data` is `{format, width, height, elements}`: `format` `skeleton` (Claude's, Excalidraw element skeletons the PWA expands) or `scene` (a saved edit: full Excalidraw elements, and `appState.viewBackgroundColor`). `width` and `height` are the frame the coordinates are in: the pixels of the JPEG sent to Claude, so the PWA lines the drawing up with the photo. `404` if there is none |
| `GET /api/captures/{id}/photos/{sha256}/drawing/versions` | Every version, newest first, as above without `data`. `producer` is the model, or `human` with its `author`; a restored version has `restored_from` |
| `PUT /api/captures/{id}/photos/{sha256}/drawing` | `{base_version, scene: {elements, appState?, width?, height?, files?}}`: save an edit as a new current `human` version, its text elements indexed for search. `base_version` is the version it was edited from (`null` if there was none): `409` with the current `version` if that is no longer current. The scene is checked (see [](../explanations/ingest.md)): only rectangle, ellipse, diamond, text, arrow, line and freedraw elements; finite numbers; Excalidraw's colours; `http(s)` links only; nesting at most 32 levels deep; valid Unicode (no lone surrogates); `files` dropped; at most 5 MB as compact JSON, else `422` and nothing is saved. `413` if the request is over 8 MB |
| `POST /api/captures/{id}/photos/{sha256}/drawing/restore` | `{version, base_version}`: make an old version current again as a new copy (versions never change). `base_version` is the current version as the client last saw it: `409` with the current `version` if it has changed, so a stale history view cannot restore over a newer edit. `404` if there is no such version; `422` unless both are integers from 1 |
| `GET /api/ingest` | The ingest queue: `{enabled, paused, reason, paused_until, jobs, spent_today_usd}` (`paused_until` is `null` while paused until *Resume*) |
| `POST /api/ingest/resume` | End a pause; returns the queue as `GET /api/ingest` |
| `DELETE /api/pages/{id or slug}` | Move a page to the trash (`204`). Its captures and files are kept |
| `POST /api/pages/{id or slug}/undelete` | Bring a page back from the trash |
| `GET /api/search?q=...&limit=20&offset=0` | `limit` at most 100; `offset` (at most 10 000) skips that many hits, for the next page. Full-text search of titles, tags, the `summary` field, bodies and what Claude read from photos (their text and descriptions): every word must match somewhere in the page, as a prefix (`vsc` finds `vscode`), wherever it stands in the query; one hit per page. Pages with every word in the title come first, then those with every word in the title, tags or summary, then by bm25. Link and image addresses in Markdown are not indexed, only their text. The query may also have `-word` or `!word` (the exact word in no part of the page), `"a phrase"` (exact), `kind:K` (a kind, or the PWA's `read`, `board`, `doc`; two mean either), `tag:T` (a tag with `T` as whole `/` parts: `tag:a` finds `a/b`, `tag:b` finds `a/b`; `tag:"two words"`), `is:personal`, `is:work` (`personal` not true), `is:claude` (written over MCP), `is:S` (status `S`), `has:image` (an image in one of its captures), `has:drawing` (a current drawing; another `has:` value matches nothing), `image:K` (a photo Claude took for kind `K`: `photo`, `whiteboard`, `handwriting`, `diagram`, `screenshot`, `document`, `other`), `after:D` and `before:D` (last edited on or after, on or before `D`: a date `YYYY-MM-DD`, a UTC day with both ends included, or a time ago such as `1d`, `2w`, `1m` (30 days), `1y` (365 days); a value that is neither matches nothing, and after `-` everything) or `date:created` (`after:` and `before:` use the creation date instead), `due:D` (a todo due on `D`, or with `<`, `<=`, `>`, `>=` before or after it: `D` is a date `YYYY-MM-DD` or `today`, `tomorrow`, `yesterday` on the server's own calendar, its local time zone (`TZ`); `due:<today` is overdue; `due:none` a todo with no due date; another value matches nothing), `priority:P` (a todo's: `high`, `medium`, `low`, or `none`; two mean either; Thoth's `urgent` means `high`); a filter after `-` excludes. `sort:updated` (last edited first), `sort:created` (newest first), `sort:title` (A to Z, ignoring the case of ASCII letters only: `é` and `É` sort apart), `sort:due` (soonest first) or `sort:priority` (high first; for both, pages without one, and pages that are not todos, come last either way) orders the results instead of best match (or newest first), with `-sort:` the other way (`-sort:created`: oldest first); the last one counts, and another value is ignored. `sort:` alone lists every page in that order. Filters alone list their pages, newest first, with the summary or the start of the text as the snippet. At most 16 distinct words with a letter or digit are used; others (`&`, `?`) are ignored. Each hit has `id`, `slug`, `title`, `kind`, `fields` (so a todo's row can show its status), `due`, `priority`, `updated_at`, `thumb` (as in `GET /api/pages`) and an HTML-escaped `snippet` with matches in `<mark>` |
| `GET /api/search/facets?q=...` | What the pages a search finds have in common: `{total, kinds: [[kind, n]], tags: [[tag, n]], personal: {work, personal}, active: [{token, key, value, neg}]}`. `tags` are the 12 most used (a tag counts for its parents too, `a` for `a/b`), leaving out those the query asks for and those on every page found; `active` are the query's filters as typed (`sort:` too) |
| `GET /api/tags` | Every tag on a page not in the trash, with the parents of `a/b` tags, and how many pages have it (or one under it): `[[tag, n]]`, in order |
| `GET /api/pages/{id or slug}/download` | The page to keep: `<slug>.md` (front matter, with a todo's `due` and `priority` if it has them, then the body), or if it has files `<slug>.zip` holding the `.md` and `files/` with the originals, linked relatively so it reads offline. Each photo is followed by Claude's description (a quote) and the text it read (a fenced block), and its drawing is beside it as `<photo name>.excalidraw` (Claude's skeleton converted approximately on the server: Excalidraw re-measures the text when it opens it) |
| `GET /api/blobs/{sha256}/uses?page={page id}` | `{pages}`: how many pages other than `page` (the trash left out) show the file, by an embed in their text or as a file of their own capture. The editor's warning when an embed is deleted. `404` if the file is not stored |
| `GET /api/blobs/{sha256}` | An original file, byte for byte, with its stored content type. `?download=1` adds a `Content-Disposition` with the name it was uploaded under |
| `GET /api/blobs/{sha256}/preview?size=2048` | A JPEG of a photo (HEIC too), turned upright and without its EXIF, at most `size` (`480` or `2048`) pixels a side. Made on first request and kept in `cache/previews/` under the data folder, which is never backed up and can be deleted at any time. Made one at a time, shrunk as it is decoded, within a memory budget that fits a 1 GB container: `422` if the file is not an image Pillow can read or would need more memory than that to decode (roughly over 50 megapixels for HEIC, 80 for PNG; JPEG is decoded shrunk and fits at any size), `503` with `Retry-After` if the decoder stays busy for 20 s. The colour profile is kept |
| `POST /mcp` | The MCP server (Streamable HTTP, stateless, JSON replies) for Claude Code sessions: see [](mcp.md). `421` if the `Host` header is not loopback or a `SCRAP_PUBLIC_URL` host, `403` for another `Origin`, `413` over 2 MB |
| `POST /share` | The PWA's share target, for when its service worker did not take the share (which it normally queues itself): saves the multipart `title`, `text`, `url` and `files` as a capture with a server-minted id, then `303` to `/` |
| `GET /`, `/recent`, `/search`, `/tags`, `/todos`, `/p/{slug}` | The PWA (`index.html`); its other files are served from the root too. `503` with build instructions if it was not built; see [](../how-to/use-the-pwa.md) |

## CLI

| Command | Does |
| --- | --- |
| `scrap serve [--host 127.0.0.1] [--port 8000]` or `scrap serve --uds PATH` | Run the service, migrating the database first. `--uds` listens only on a Unix socket (mode 600, in a folder of its own closed to others) and cannot be combined with `--host`/`--port` |
| `scrap backup DIR` | Consistent snapshot of the database (SQLite online backup) plus `files/`; safe while serving |
| `scrap restore DIR [--force]` | Restore a backup into an empty data folder, after checking its integrity and that its schema is not newer than this scrap. `DIR` may be read-only: only a copy of its database, made in the data folder, is opened. `--force` replaces the whole database (pages added since the backup are lost; files are kept); stop scrap first, or a running server goes on writing to the replaced database and those writes are lost |
| `scrap ingest-once IMAGE [--save FILE]` | Send one image file to Claude as ingest would, without a database, and print the outcome in numbers only (tokens, cost, seconds, counts of lines, elements and warnings); `--save FILE` also writes the full result, including all the text Claude read from the image, to a new file with mode 600 (an existing file is refused), created before the paid call. Needs `ANTHROPIC_API_KEY` |
| `scrap import DIR [--dry-run] [--ingest]` | Import a Thoth vault: each content page with its kind, fields, tags, dates, links (as `[[slug\|label]]`) and images; see [](../how-to/import-a-vault.md). `--dry-run` writes nothing and prints counts (by kind and folder) and every problem (broken links, unreferenced images, unmapped fields...). A second run imports only pages not imported before. `--ingest` also queues the images for Claude |
| `scrap export DIR` | One Markdown file per page, front matter (with a todo's `due` and `priority`) and links to its originals copied into `DIR/files/`, with each photo's description, text and `.excalidraw` drawing as in the page download. Export only: never read back |

Every command takes `--data-dir` (default `$SCRAP_DATA_DIR`, else `./data`), which holds
`scrap.db` and `files/` (originals by SHA-256).

## Settings

| Variable | Default | Meaning |
| --- | --- | --- |
| `SCRAP_DATA_DIR` | `./data` | The data folder |
| `SCRAP_WEB_DIR` | the packaged PWA | Serve the PWA from this folder instead: a new build there shows without a restart |
| `SCRAP_PUBLIC_URL` | unset | The address the service is reached at, e.g. `https://host.tailnet.ts.net:8446` (several, comma separated). `/mcp` answers only requests whose `Host` is loopback or one of these (DNS rebinding protection), and the first makes the page URLs MCP tools return; without it they are paths (`/p/<slug>`) |
| `SCRAP_MAX_UPLOAD_MB` | `50` | Largest request body (a capture's files together), enforced as it arrives: `413` |
| `SCRAP_INGEST` | `off` | `on` starts the worker that sends photos to Claude (photos are queued either way) |
| `ANTHROPIC_API_KEY` | | The key for the Claude API; keep it in the service user's mode-600 env file |
| `SCRAP_VISION_MODEL` | `claude-opus-5-5` | The model photos are sent to |
| `SCRAP_BUDGET_DAY_USD` | `3` | Daily spend, from recorded usage, after which the queue pauses until UTC midnight |
| `SCRAP_NOTIFY_URL` | unset | If set, the first pause of an episode POSTs one fixed line naming its reason here (an ntfy topic works) |
